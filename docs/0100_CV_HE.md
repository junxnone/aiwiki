# Histogram Equalization 直方图均衡

- 图像直方图均匀分布
- 增强图像 - 更好的对比度
- CDF -  [cumulative distribution function](https://en.wikipedia.org/wiki/Cumulative_distribution_function)  - 累积分布函数
 - HE - `Histogram Equalization`
 - AHE - `Adaptive Hisogram Equalization`
 - CLAHE - `Contrast Limited Adaptive Hitogram Equalization`
- 图像的直方图本身（横轴灰度值、纵轴像素数量）见 [Histogram 图像直方图](0342_Media_Image_Histogram)，本文直接在直方图分布基础上讨论"怎么调整它"

## Contrast Stretching
- 8 bit image 最小值 `Vmin = 0` `Vmax = 255`
- image 中 Pixel 最小值 `Pmin`, 最大值 `Pmax`
- `cutoff fraction` - 小于 `Pmin = histogram_peak * cutoff_fraction` 的值忽略掉

`Pout = (Pin - Pmin)(Vmax-Vmin)/(Pmax-Pmin) + Vmin`

**和 HE 的区别**：Contrast Stretching 只是把现有的灰度区间**线性拉伸**到全量程 `[0, 255]`（一次线性映射），不改变灰度分布的"形状"；而下面的 HE 是**非线性**映射，直接按累积分布函数重新分配灰度值，让直方图趋于均匀——两者都是"增强对比度"，但 Stretching 更温和、保留原有分布特征，HE 更激进、能把分布很不均匀（比如集中在暗部）的图像拉开差距。

**直觉理解**：映射函数就是原图灰度的**累积分布函数（CDF）**本身（归一化到 `[0, 255]`）——直方图里像素数量多的灰度区间，CDF 曲线在那一段斜率大，拉伸效果就强；像素数量少的区间 CDF 斜率小，几乎不怎么变。效果是：原本挤在一小段灰度区间里的大多数像素被"拉开"分布到更大的范围，图像看起来对比度更强。

**彩色图像的坑**：不要直接对 R/G/B 三个通道分别做 HE——这样会破坏三通道之间原有的比例关系，导致颜色失真（偏色）。正确做法是转到 HSV/YCrCb 等"亮度和颜色分离"的色彩空间，只对亮度通道（V 或 Y）做 HE，再转换回 RGB。

## AHE - Adaptive Hisogram Equalization
- 自适应直方图均衡化
- 考虑到局部图像区域 - `WxW` 窗口
- LAHE - Local Area HE

![image](https://user-images.githubusercontent.com/2216970/100970111-3f070a00-356f-11eb-9384-a5183b07278a.png)

**为什么需要 AHE**：普通 HE 是基于**整张图**的直方图算出一个全局映射函数，如果图像里有的区域偏暗、有的区域偏亮（比如逆光拍摄），全局映射对两边都不是最优——对暗部有利的映射对亮部可能过度增强。AHE 的思路是把图像切成很多个小窗口，**每个窗口单独做一次 HE**，让每个局部区域都能得到针对自己直方图的最优映射，所以在光照不均匀的图像上效果比全局 HE 好得多。

**AHE 自己的新问题**：如果某个窗口恰好落在一片几乎纯色的平坦区域（比如蓝天、阴影），这个窗口的直方图会高度集中在很窄的灰度范围内，HE 的映射函数会把这一点点差异剧烈放大——结果是平坦区域里原本看不见的噪声被放大成很明显的噪点。这正是下面 CLAHE 要解决的问题。

## CLAHE - Contrast Limited Adaptive Hitogram Equalization
- 限制对比度自适应直方图均衡化
- 将直方图中超过阈值的部分平均分配到各灰度级

![image](https://user-images.githubusercontent.com/2216970/100969603-4843a700-356e-11eb-961d-40725328c002.png)

**具体怎么"限制"**：对每个局部窗口的直方图设一个高度阈值（Clip Limit），直方图里超过这个阈值的部分被"削平"，削掉的这些像素计数**平均重新分配**到整个直方图的所有灰度级上（而不是直接丢弃，否则总像素数对不上）。这样一来，像 AHE 里那种集中在窄范围的尖峰直方图就被削平、不会再产生过度放大的映射斜率，从根本上压制了噪声被放大的问题。

**分块边界的处理**：CLAHE 对每个小块（tile）各自做限制对比度的 HE，但不是直接拼起来——块与块交界处会有明显的拼接痕迹（亮度突变），标准实现（包括 OpenCV）会在相邻块的映射结果之间做**双线性插值**，让块边界过渡平滑，看不出分块痕迹。

## 怎么选

| 场景 | 推荐方法 |
|---|---|
| 只想整体调整一下对比度、不想丢失原有分布特征 | Contrast Stretching |
| 整张图光照基本均匀，只是普遍偏暗/偏亮/对比度低 | HE（最简单，一步到位） |
| 光照不均匀（逆光、局部阴影），且不太担心噪声 | AHE |
| 光照不均匀，且图像本身噪声较明显（大多数实拍照片属于这种） | **CLAHE**（工程实践里最常用，默认优先选它而不是 AHE），OpenCV 的具体用法见 [OpenCV CLAHE](0341_OpenCV_CLAHE) |
| 需要保持原图整体亮度不变（普通 HE 会把亮度也拉偏，比如暗图均衡化后可能变得过亮） | BBHE（见下文） |
| 想让图像匹配某个指定的目标直方图（而不是追求"均匀分布"） | 直方图规定化/匹配（见下文） |

## 保持亮度的 HE 变体：BBHE

普通 HE 有个副作用：它只保证均衡化后直方图趋于均匀，**不保证图像的平均亮度不变**——一张本来偏暗的图像做完 HE 之后，平均亮度往往会被整体拉高，这在需要"增强细节但不改变整体观感亮度"的场景（如电视/显示器的图像增强、医学影像）里是不希望看到的。

**BBHE（Bi-directional/Brightness preserving Bi-Histogram Equalization）**的思路：先按原图的**均值灰度**把直方图从中间切成两半（低于均值的一半、高于均值的一半），然后对这两部分**分别独立做 HE**，低的部分映射到 `[0, 均值]`，高的部分映射到 `[均值, 255]`。这样均衡化后图像的均值大致还停留在原来的均值附近，兼顾了"增强对比度"和"保持原有亮度"两个目标。后续还有 DSIHE（用中位数而不是均值切分）、RMSHE（递归多次切分）等变体，思路都是"先合理分段，再分段独立均衡化"。

## 直方图规定化（Histogram Matching / Specification）

HE 的目标是"让直方图趋于均匀分布"，但均匀分布不一定是视觉上最好看或最适合后续处理的分布。**直方图规定化**把目标从"均匀"换成"匹配一个指定的目标直方图"——比如让一批不同光照条件下拍摄的图像都匹配到同一个参考直方图，使它们风格统一（常用于多张图像拼接前的色调统一、或者让处理结果匹配某个期望的对比度分布）。

做法是分别求出原图和目标直方图各自的 CDF，对原图每个灰度值，先通过原图的 CDF 找到对应的累积概率，再反查目标直方图的 CDF，找到具有相同累积概率的灰度值作为映射结果——HE 可以看作"目标直方图正好是均匀分布"这个特例。

## 代码示例（OpenCV）

```cpp
// 全局 HE，只能用于单通道（灰度）图像
cv::equalizeHist(gray, dst);

// CLAHE：clipLimit 是对比度限制阈值，tileGridSize 是分块大小
cv::Ptr<cv::CLAHE> clahe = cv::createCLAHE(2.0, cv::Size(8, 8));
clahe->apply(gray, dst);

// 彩色图像：先转到 YCrCb，只对亮度通道 Y 做 CLAHE，再转换回来
std::vector<cv::Mat> channels;
cv::cvtColor(src, ycrcb, cv::COLOR_BGR2YCrCb);
cv::split(ycrcb, channels);
clahe->apply(channels[0], channels[0]);
cv::merge(channels, ycrcb);
cv::cvtColor(ycrcb, dst, cv::COLOR_YCrCb2BGR);
```
