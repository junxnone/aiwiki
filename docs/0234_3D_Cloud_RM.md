# Rotation Matrix 旋转矩阵


- **pcl 旋转平移矩阵 (4x4)**

![image](https://user-images.githubusercontent.com/2216970/118071034-912f3f80-b3d9-11eb-84c2-c64f753886fe.png)


```
            ↓-------> This column is the translation
    | 1 0 0 x |  \
    | 0 1 0 y |   }-> The identity 3x3 matrix (no rotation) on the left
    | 0 0 1 z |  /
    | 0 0 0 1 |    -> We do not use this line (and it has to stay 0,0,0,1)
```
- 最后一行的 `|0 0 0 1|` 不使用

### 平移
- (x, y z) 为平移参数
- 每个值表示沿对应轴的平移量

### 旋转

- 沿 x/y/z 轴旋转参数由矩阵中左上角的 `3x3` 子矩阵表示
- α/β/γ 分别表示沿 x/y/z 轴旋转的角度

## 旋转矩阵的性质

旋转矩阵 $R$（左上角 3x3 子矩阵）不是任意 3x3 矩阵，必须满足两个约束，合在一起构成所谓的 **SO(3)**（特殊正交群）：

- **正交性**：$R^T R = I$（转置等于逆），意味着旋转不改变向量的长度和夹角——这是"刚体运动"的数学定义；
- **行列式为 1**：$\det(R) = 1$（排除镜像反射这种行列式为 -1 的变换）。

这两条约束也是配准算法（如 ICP）求解出的变换矩阵必须满足的——如果求解结果不满足正交性，通常意味着算法实现或数值计算有问题。

## 旋转的几种表示方式对比

矩阵只是旋转的一种表示方式，实践中还有几种常用替代表示，各有取舍：

| 表示方式 | 参数个数 | 优点 | 缺点 |
|---|---|---|---|
| **旋转矩阵（Rotation Matrix）** | 9（实际自由度 3） | 直接参与矩阵乘法/变换计算，无需额外转换 | 参数冗余（9 个数只有 3 个自由度），插值不直观 |
| **欧拉角（Euler Angles，即上文的 α/β/γ）** | 3 | 直观、符合人类对"绕哪个轴转多少度"的理解 | 存在**万向锁（Gimbal Lock）**——当某个轴旋转 90° 时，会丢失一个自由度，导致两个轴的旋转效果重合，无法再表示某些姿态；旋转顺序（XYZ/ZYX/...）不同，结果也不同，容易出错 |
| **四元数（Quaternion）** | 4（单位四元数，实际自由度 3） | 没有万向锁问题，插值（Slerp）平滑自然，数值稳定性好 | 不直观，无法直接从数值看出"绕哪个轴转了多少度" |
| **轴角（Axis-Angle）** | 4（旋转轴 3 + 旋转角 1） | 直观——直接表示"绕某个轴转多少度" | 同一个旋转可以有多种等价表示（角度 + 2π 或者反向轴 + 负角度），不适合直接插值 |

实践中的典型选择：**人机交互/参数标注**用欧拉角（直观），**内部计算/插值**用四元数或旋转矩阵（避免万向锁），**ICP 等配准算法输出**通常直接是旋转矩阵（或等价的 4x4 齐次变换矩阵），因为它可以直接左乘到点坐标上完成变换，不需要额外转换。

## 旋转的组合：顺序很重要

多个旋转依次叠加时，**旋转矩阵的乘法不满足交换律**——先绕 x 轴转再绕 y 轴转，和先绕 y 轴转再绕 x 轴转，结果通常不一样。实践中还要区分：

- **外旋（Extrinsic）**：每次都绕固定的世界坐标系轴旋转；
- **内旋（Intrinsic）**：每次都绕物体自身当前姿态下的坐标轴旋转（每次旋转后坐标系也跟着转动）。

同一组欧拉角数值，按外旋和内旋解释出来的最终姿态是不同的——这也是欧拉角容易出错的另一个原因，使用时必须明确约定旋转顺序和内/外旋方式。

## 和点云配准/拼接的关系

[点云拼接](0286_3D_Cloud_Merge) 里配准算法求解出的"变换矩阵"，本质上就是这里的 4x4 齐次矩阵——左上角 3x3 是旋转（必须满足上面的正交性约束），最后一列是平移。拼接流程里先用粗配准得到一个初始的旋转平移矩阵，再用 ICP 迭代精化这个矩阵，最终目的都是求出这样一个满足 SO(3)/SE(3)（特殊欧氏群，旋转+平移）约束的变换，把源点云变换到目标点云所在的坐标系。
