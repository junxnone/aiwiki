# GaLore / ReLoRA：用低秩技巧做全参数训练

> 本文是 [大模型微调总览](0410_LM_FT) 的深入篇。GaLore 和 ReLoRA 都借用了"低秩"这个 LoRA 系方法的核心思想，但目标完全不同——它们不是 PEFT，最终训练出来的模型权重仍然是**全参数、全秩**的，低秩技巧只是用来省训练时的显存/效率，不是为了减少可训练参数量，所以本页单独讨论，不归在 [LoRA 家族](0406_LM_FT_LoRA) 里。

## 和 LoRA 的本质区别

[LoRA](0406_LM_FT_LoRA) 假设**权重更新量** `ΔW` 本身是低秩的，训练过程中权重的可表达能力被限制在一个低秩子空间里，这是 PEFT 方法"参数少"的来源，代价是理论上限低于全参数微调（能拟合的 `ΔW` 范围有限）。GaLore 和 ReLoRA 都不做这个假设——它们承认最终需要的权重更新可以是高秩/全秩的，只是想办法用低秩的中间过程把训练显存/效率变得更省，最终权重和全参数训练没有本质区别。

## GaLore：压缩的是梯度，不是权重

GaLore（Zhao et al. 2024）的观察是：训练过程中，权重矩阵本身不一定低秩，但**梯度矩阵**在训练过程中会表现出缓慢变化的低秩结构。于是 GaLore 不去近似权重，而是用两个投影矩阵 `P`、`Q` 把梯度矩阵 `G` 投影到一个低秩子空间里：

- Adam 这类优化器的状态（一阶/二阶动量）本来就是按梯度的形状逐元素维护的，梯度被投影到低秩子空间后，优化器状态的存储开销也跟着大幅下降；
- 权重本身依然是全参数更新（投影后的低秩梯度会被映射回原始形状去更新权重），**不是** PEFT；
- 实测能把优化器状态的显存开销降低 65.5%，配合 8bit 优化器，总训练显存相比 BF16 基线能降低 63.3%，论文作者展示了在单张 24GB 显存的消费级 GPU 上预训练 7B 模型（不借助模型并行、梯度检查点或 CPU 卸载）的可行性。

这和 QLoRA 的"省显存"方式是两条完全不同的路：QLoRA 省的是**权重存储**（量化基座权重，配合 LoRA 只训练少量参数），GaLore 省的是**优化器状态**（全参数训练，但梯度/动量用低秩压缩存储）。

## ReLoRA：多次低秩更新叠加出高秩结果

ReLoRA（Lialin et al. 2023）走的是另一条路：单次 LoRA 更新确实是低秩的，但如果**反复做**"用 LoRA 训练一段时间 → 把这次的低秩更新 `BA` 合并回基座权重 → 重置 LoRA 的 A、B 重新开始下一轮"，多轮低秩更新累加起来，总的权重变化在理论上可以达到任意高的秩——这是"Stack More Layers Differently"这个别名的含义：用很多次"矮"的低秩更新堆叠出一个"高"的总变化量。

具体训练流程包含几个关键组件：

- 训练开始时先做一段**全秩预热**（直接全参数训练一小段，而不是从零开始套 LoRA）；
- 之后反复执行"LoRA 训练一段步数 → 合并回基座权重 → 重置 LoRA 参数"这个循环（"restart"）；
- 配合锯齿状（jagged）的学习率调度和**部分优化器状态重置**（每次 restart 时不完全清空优化器动量，只重置一部分），缓解每次重置 LoRA 带来的训练震荡。

实测 ReLoRA 能比常规全参数训练节省每块 GPU 最多 5.5GB 显存，训练速度提升 9%~40%（取决于模型规模和硬件），且论文观察到**模型规模越大，ReLoRA 的效率优势越明显**，在百亿参数级别的预训练场景比小模型更有价值。

## 怎么选

| 场景 | 推荐 |
|---|---|
| 要做下游任务的参数高效微调，最终只想要一小份 adapter 权重 | 回到 [LoRA](0406_LM_FT_LoRA) 家族，不需要 GaLore/ReLoRA |
| 想做全参数（继续）预训练，但显存/优化器状态开销是瓶颈 | GaLore——不改变"全参数训练"这个目标，只是省优化器状态显存 |
| 想从零训练/继续预训练一个大模型，且愿意接受"训练流程里反复合并-重置"的工程复杂度来换训练速度 | ReLoRA |
| 只是常规下游任务微调，没有预训练/继续预训练的需求 | GaLore/ReLoRA 的收益场景和常规 PEFT 微调不太重合，优先级低于 LoRA 系方法 |
