## 0. 问题与分类

### 0.1 时间序列任务

| 任务 | 输入 → 输出 | 备注 |
|---|---|---|
| 预测（forecasting） | 历史窗口 → 未来 H 步 | 本文主线；分点预测和概率预测 |
| 异常检测 | 序列 → 每点/每窗异常分数 | 多为无监督或半监督，标签稀缺且常有标注偏差 |
| 分类 | 整条序列 → 类别 | UCR/UEA 档案是标准基准 |
| 填补（imputation） | 带缺失序列 → 补全序列 | 常与概率生成模型结合（CSDI） |
| 表示学习 | 序列 → 向量 | 为下游任务提供特征（TS2Vec） |

各任务的典型行业应用如下。这些是场景类别的归纳 [经验]，不是具体案例或效果数字。

**预测**

| 行业 | 预测对象 | 常见做法与关注点 |
|---|---|---|
| 零售 / 电商 | SKU×门店的日/周销量、促销影响 | 序列条数极多，适合全局模型（LightGBM、TFT、N-HiTS）；价格、促销、节假日是已知未来协变量；常需分层一致性（门店→区域→总量） |
| 能源 / 电力 | 负荷、风电光伏出力、电价 | 短期（小时–日）负荷预测对调度最关键；新能源出力强依赖气象协变量；常需概率预测（分位数）支撑备用容量决策 |
| 供应链 / 物流 | 需求、库存、运量、到货时间 | 间歇性需求（大量零值）要用专门方法；决策目标是服务水平，应评估分位数而非 MSE |
| 金融 | 波动率、现金流、交易量 | 信噪比低，点预测难；GARCH 类波动率模型与风险度量（VaR）结合；注意回测中的前视泄漏 |
| 交通 / 出行 | 路网流量、网约车需求、客流 | 空间-时间依赖强，常用图结构模型（本文未展开）；节假日和天气影响大 |
| 云 / IT 运维 | 容量、QPS、资源用量 | 用于弹性伸缩和容量规划；多周期（日/周）季节明显，统计模型与 Prophet 类方法常够用 |
| 医疗 / 公共卫生 | 门诊量、床位占用、传染病发病 | 样本量小、分布漂移大；需要不确定性区间，可解释性要求高 |
| 气象 / 水文 | 温度、降水、径流 | 物理模型（数值预报）为主，数据驱动模型用于后处理或补充 |

**异常检测**

| 行业 | 检测对象 | 备注 |
|---|---|---|
| 制造 / 流程工业 | 设备传感器（振动、温度、电流）的异常，预测性维护 | 故障样本极少，多为无监督；需要容忍工况切换导致的漂移 |
| 云 / IT 运维（AIOps） | 服务指标（延迟、错误率）、日志计数 | 告警疲劳是主要痛点，误报率比召回率更影响落地 |
| 金融风控 | 交易流水中的欺诈、异常资金流 | 常与图和规则系统结合；标签延迟 |
| 网络安全 | 流量、登录行为的异常 | 对抗性强，攻击者会适应检测器 |
| 医疗监护 | ICU 生命体征、可穿戴设备心率 | 需要低延迟和个体化基线 |

**分类**

| 行业 | 任务 |
|---|---|
| 医疗 | 心电（ECG）、脑电（EEG）的心律失常/癫痫发作分类；睡眠分期 |
| 可穿戴 / 消费电子 | 加速度计信号的人体活动识别（走、跑、跌倒） |
| 制造 | 振动波形的故障类型诊断（轴承、齿轮箱），工况识别 |
| 语音 / 声学 / 遥感 | 声音事件分类；卫星时间序列的作物类型或土地利用分类 |

**填补**

| 行业 | 缺失来源 |
|---|---|
| 医疗 | 电子病历中检验指标测量稀疏、不规则（常是"未测"而非"随机丢失"） |
| 环境 / 气象 | 站点传感器故障、通信中断导致的空气质量、气温缺失 |
| 工业 | 传感器掉线、PLC 通信丢包 |
| 交通 | 路段检测器缺数据 |

填补要先分清缺失机制：随机丢失可用插值或 CSDI 一类生成式模型；信息性缺失（"没测"本身含义）直接填补会引入偏差，应把缺失掩码作为特征 [经验]。

**表示学习**

| 行业 | 用途 |
|---|---|
| 医疗 / 可穿戴 | 标注昂贵时，用自监督表示配合少量标签做下游分类 |
| 制造 | 设备运行状态的聚类与相似工况检索，跨设备迁移 |
| 零售 / 用户行为 | 序列嵌入用于客户分群、相似商品检索 |

### 0.2 几组关键区分

下面用一个贯穿的小场景来解释：一家连锁便利店，有 500 家门店、每家 2000 个 SKU，每天记录销量，要为补货做预测。

#### 单变量 vs 多变量

- **单变量**：每个时间点只有一个数。例如"A 店可乐的日销量"，只用它自己的历史预测未来。
- **多变量**：每个时间点是一个向量，多个变量同时记录。例如 A 店同一天的"可乐销量、气温、客流量、促销标记"。
- **要问的问题**：预测可乐时，要不要利用雪碧的销量？气温高时两者通常一起涨，这是**变量间依赖**，用上可能更准；但变量一多（2000 个 SKU），两两建模成本高，还容易过拟合。
- **反直觉的事实**：把多变量拆成一条条单变量、共享同一套参数分别预测（通道独立，如 PatchTST），在不少基准上并不输给显式建模变量关系的模型。因此"是不是多变量数据"不等于"必须用多变量模型"，详见 §4.6。

#### 局部模型 vs 全局模型

- **局部模型**：一条序列一个模型。给"A 店可乐"拟合一个 ETS，再给"A 店雪碧"拟合另一个，共 100 万个模型，每个只用自己那条历史。
- **全局模型**：所有序列共用一个模型，用"门店、品类、价格、星期几"等特征区分个体。LightGBM、DeepAR、N-BEATS、基础模型都是这种。
- **差别在哪**：新品上架只有两周历史，局部模型没法拟合，全局模型却能借用"同类饮料新品通常怎么爬坡"的经验（冷启动）。反过来，如果每条序列各有独特规律、又很长（如 5 年日数据），局部模型简单稳妥。序列多而每条短，全局模型通常更有利 [经验]。
- **代价**：全局模型要把所有序列放在一起训练，对尺度差异大的序列（日销 5 件与 5000 件）需要做归一化。

#### 点预测 vs 概率预测

- **点预测**：给一个数。"明天可乐卖 120 瓶"。
- **概率预测**：给分布或分位数。"明天 P10=95、P50=120、P90=160"。
- **为什么决策需要后者**：补货要在"缺货损失"与"积压损失"之间权衡。假如缺货一瓶亏 3 元、积压一瓶亏 1 元，最优备货量应取 P75 附近（临界比 3/(3+1)），而不是 P50 的 120。只有点预测，就无法算这个量。能源调度的备用容量、云资源的容量规划同理。
- **怎么评估**：点预测看 MAE/MASE；概率预测看分位数损失、CRPS，以及**校准**，即标称 80% 的区间是否真有 80% 的时候覆盖实际值（§5）。

#### 短期 vs 长期

- **短期**：提前几步到几十步，如"未来 24 小时的用电负荷"。
- **长期（LTSF）**：论文里常见 96、192、336、720 步，如"用过去 336 小时预测未来 720 小时（30 天）"。
- **注意两点**：一是预测越远越不确定，长期预测的价值往往在趋势和季节形状，而不是逐点精度；二是 LTSF 基准（ETT、Electricity、Traffic 等）上的结果与真实业务有距离——业务里真正难的往往是促销、节假日、突发事件这类**未来事件**，仅靠历史外推的模型对此无能为力（§8.3、§10）。
- **与"多步策略"的关系**：多步预测可以递归（预测一步、把结果喂回去再预测下一步，误差会累积）或直接（一次输出全部 horizon，PatchTST、DLinear、N-BEATS 属此类）。

#### 协变量

协变量是"除了目标序列自身历史之外"的输入。仍以便利店为例：

| 类型 | 例子 | 特点 |
|---|---|---|
| 静态协变量 | 门店所在城市、门店面积、SKU 所属品类 | 不随时间变；帮助模型区分个体，是全局模型的"身份证" |
| 已知未来协变量 | 未来的节假日、已排定的促销、计划降价 | 预测时就知道未来取值，信息量最大，务必用上 |
| 仅历史协变量 | 过去的客流、过去的气温、竞品历史价格 | 未来值未知；若要用，需先预测它，或只用历史部分 |

- **为什么是选型的硬指标**：同样是"双十一前一周预测销量"，不带"促销标记"的纯历史模型几乎必然低估；而 ARIMA（基础形式）、N-BEATS（基础形式）、大多数零样本基础模型对已知未来协变量的支持有限或没有，TFT、LightGBM、DeepAR、TimeXer 则明确支持。选模型前先列出自己有哪几类协变量，再看模型是否吃得下 [经验]。

## 1. 经典统计模型

本节是概览；各方法的公式、直觉、优缺点与发展脉络见专文 [classical](0604_ML_Tasks_TimeSeries_Classical)。

这一层在工业界依然是**默认基线**，且在 M 系列预测比赛中长期表现稳健。以下为编者对标准教材内容的归纳，文献细节待核实。

| 模型 | 核心思想 | 适用 | 局限 |
|---|---|---|---|
| **ARIMA / SARIMA** | 差分使序列平稳后，用自回归（AR）和滑动平均（MA）项建模；SARIMA 加季节项。Box–Jenkins 方法论（1970 年专著，待核实）：识别 → 估计 → 诊断 | 单序列、线性、短期 | 手工定阶或 auto-ARIMA；多季节、非线性弱；每条序列单独拟合 |
| **指数平滑 / ETS** | 水平、趋势、季节分量按指数衰减权重更新；Holt–Winters 是经典形式；状态空间化后可得预测区间 | 趋势 + 季节明显的业务数据 | 对突变和外生变量不敏感 |
| **Theta** | 把序列分解为不同曲率的"theta 线"外推后组合 | 作为 M 系列比赛中的强基线（待核实） | 功能单一 |
| **状态空间 / Kalman 滤波** | 隐状态按线性高斯动力学演化，观测为其带噪投影；结构时间序列模型（STS）由此而来 | 在线滤波、缺失值、传感器融合 | 非线性需 EKF/UKF/粒子滤波 |
| **VAR / VECM** | 多变量自回归，协整关系用误差修正 | 少量宏观/经济变量 | 参数随变量数平方增长 |
| **GARCH 族** | 对条件方差建模 | 金融波动率 | 只管二阶矩 |
| **Prophet** | 趋势 + 傅里叶季节 + 节假日的可加回归（Taylor & Letham，2017/2018，待核实） | 业务指标、分析师可调参 | 非深度基线对比里常被更强方法超越 [经验] |

工具：statsmodels、statsforecast（高性能 ETS/ARIMA/Theta 实现）、sktime、darts（待核实具体版本与接口）。

**为什么必须先跑它们**：Audibert 等人在异常检测上、TFB/DLinear 在预测上都表明，简单方法常能打平甚至胜过复杂深度模型（见 §7）。

## 2. 机器学习与全局模型

本节是概览；详解见专文 [ml](0605_ML_Tasks_TimeSeries_ML)。

### 2.1 梯度提升树 + 特征工程

把预测变成表格回归：滞后值、滚动统计、日历特征、协变量作为列，用 LightGBM / XGBoost 训练，多步预测用递归、直接（每个 horizon 一个模型）或多输出策略。M5 比赛前列方案多以 LightGBM 为主（待核实）。

- 优点：快、对异构协变量和类别特征友好、可解释（特征重要性）、CPU 即可 [经验]。
- 缺点：外推能力弱（树模型不能预测训练范围之外的趋势，需先去趋势/差分）；特征工程靠人。

### 2.2 ROCKET 系（分类）

ROCKET [V: 1910.13051]：大量随机卷积核提取特征，再接线性分类器；训练极快，在 UCR 档案上精度很强。MiniRocket 等后续版本进一步提速。适合作为时序**分类**的第一选择。

### 2.3 ES-RNN（M4 冠军）

Smyl 的 ES-RNN 把指数平滑的分层参数与 RNN 混合，获 M4 比赛冠军（IJF 2020，待核实）。它是"统计 + 深度混合"路线的早期里程碑，也是 N-BEATS 等纯深度方法证明自己的对照点。

## 3. 深度学习之前的铺垫：RNN 与 CNN

深度学习各架构的原理、公式与对比见专文 [deep](0606_ML_Tasks_TimeSeries_Deep)（§3 与 §4 的内容在该文中按架构重新组织）。

### 3.1 RNN / LSTM / GRU 与 DeepAR

RNN 逐步更新隐状态，LSTM/GRU 用门控缓解梯度消失。**DeepAR** [V: 1704.04110] 是该路线最有影响的工作：自回归 RNN 输出每步的分布参数（如高斯、负二项），在大量相关序列上训练**一个全局模型**，直接给出概率预测。

- 优点：天然概率预测、支持协变量、冷启动序列可借用全局参数。
- 缺点：顺序计算难并行；自回归推理的误差累积；长序列上依赖建模不及 Transformer/线性模型 [经验]。

### 3.2 TCN

Bai 等人的实证研究 [V: 1803.01271] 表明，因果膨胀卷积的通用 TCN 架构在多种序列建模任务上可与典型 RNN 相当或更好，且可并行、感受野可控。之后 CNN 路线在时序上的代表是 TimesNet（§5.3）。

## 4. 现代深度预测模型

详解见 [deep](0606_ML_Tasks_TimeSeries_Deep)（MLP/线性见其 §3.3，Transformer 见 §3.4，状态空间见 §3.5）。

### 4.1 纯 MLP 路线：N-BEATS / N-HiTS

- **N-BEATS** [V: 1905.10437]：全连接块堆叠，双重残差；每块输出"回看补偿"（backcast）和预测（forecast）；有可解释版本（趋势/季节基函数）。纯深度、无时间序列专用组件，却在 M 系列数据上竞争力强。
- **N-HiTS** [V: 2201.12886]：在 N-BEATS 上加入多速率输入池化与层级插值，让不同块负责不同频率，降低长 horizon 的计算量并改善精度。
- 适用：单变量或弱协变量、需要强基线的场景；工程上易训练 [经验]。

### 4.2 Transformer 路线：从"高效注意力"到"patch"

**第一阶段（2020–2022）：为长序列降低注意力复杂度。**
- **Informer** [V: 2012.07436]：ProbSparse 自注意力、蒸馏操作、一次性生成式解码器，用于长序列预测（LSTF）。
- **Autoformer** [V: 2106.13008]：序列分解模块内置于网络，用自相关（Auto-Correlation）机制替代点对点注意力。
- **FEDformer** [V: 2201.12740]：在频域做增强的分解 Transformer，利用傅里叶/小波变换。

**转折点：DLinear 质疑。** *Are Transformers Effective for Time Series Forecasting?* [V: 2205.13504] 提出 DLinear / NLinear 这类极简的单层线性模型（分解 + 线性），在其选定的长期预测基准上优于当时的 Transformer 方法；作者推测自注意力的置换不变性会丢失时序顺序信息。这篇论文改变了领域的叙事：**后续论文几乎都必须与线性基线对比**。

**第二阶段（2022 年后）：重新设计 token。**
- **PatchTST** [V: 2211.14730]：把序列切成 **patch** 作为 token，并采用**通道独立**（每个变量作为单独序列、共享权重）。patch 化缩短注意力序列长度、保留局部语义；通道独立降低过拟合。
- **iTransformer** [V: 2310.06625]：**倒置**——把每个变量的整条序列嵌入为一个 token，注意力在变量之间做，前馈网络沿时间做；不改 Transformer 结构，只改输入组织。
- **TimeXer** [V: 2402.19072]：把外生变量与内生序列分别处理，用于带外生变量的预测。
- **SOFTS** [V: 2404.14197]：用"序列核心"（series-core）融合替代变量间的两两注意力，降低复杂度。
- **TFT** [V: 1912.09363]：Temporal Fusion Transformer，针对**多 horizon、含静态/已知未来/观测协变量**的预测，带变量选择与注意力可解释性，是业务预测里最常被引用的 Transformer 变体之一。

### 4.3 混合 MLP 路线：TSMixer / TimeMixer

- **TSMixer** [V: 2303.06053]：全 MLP，交替做时间混合与特征（变量）混合，强调简单高效。
- **TimeMixer** [V: 2405.14616]：可分解的多尺度混合，把季节和趋势分量在不同尺度上分别混合再汇总。

### 4.4 通用骨干：TimesNet

**TimesNet** [V: 2210.02186]：用傅里叶变换找主周期，把一维序列按周期折叠成二维张量，用 2D 卷积同时捕捉周期内与周期间变化。目标是预测、填补、分类、异常检测的**统一骨干**。

### 4.5 状态空间模型（SSM）与 Mamba

- **S4** [V: 2111.00396]：结构化状态空间层，对长序列建模高效。
- **Mamba** [V: 2312.00752]：让 SSM 参数依赖输入（选择性），配合硬件感知的扫描算法，实现线性时间序列建模。
- 时序应用：S-Mamba 等 [V: 2403.11144 *Is Mamba Effective for Time Series Forecasting?*]。该方向的结论目前**并不统一**：在部分基准上有竞争力，但相对强 MLP/Transformer 基线的稳定优势仍需更多独立验证 [经验]。

### 4.6 多变量建模：通道独立 vs 通道混合

这是近年最核心的设计争议：

| 策略 | 代表 | 直觉 | 风险 |
|---|---|---|---|
| 通道独立（CI） | PatchTST、DLinear | 每个变量共享同一套参数各自预测，参数少、鲁棒 | 完全忽略变量间关系 |
| 通道混合/依赖（CD） | iTransformer、TSMixer、Crossformer 等 | 显式建模变量交互 | 变量多时容易过拟合、成本高 |

[经验] 常见情形：变量数多、每条序列相对独立时 CI 更稳；变量间有明确物理耦合（如多个传感器测同一设备）时值得试 CD。无论哪种，**用自己的验证集决定**，不要照搬论文结论。

### 4.7 一个实用训练细节：可逆归一化

非平稳序列的分布漂移问题常通过**可逆实例归一化（RevIN，ICLR 2022，待核实）**缓解：输入按每个样本做标准化，输出再反归一化。PatchTST 等众多近期模型都采用类似做法 [经验]。

## 5. 概率预测与生成式模型

生成式模型（VAE、GAN、流、扩散、流匹配）的详解见专文 [generative](0607_ML_Tasks_TimeSeries_Generative)；区间与共形预测见 [classical §3.15](0604_ML_Tasks_TimeSeries_Classical)。

点预测不足以支撑决策时，需要预测分布：

| 方法族 | 代表 | 说明 |
|---|---|---|
| 参数化分布输出 | DeepAR [V] | 输出分布参数，最大化似然 |
| 分位数回归 | TFT [V]、N-BEATS 变体 | 直接预测若干分位数，用分位数损失 |
| 扩散模型 | **TimeGrad** [V: 2101.12072]、**CSDI** [V: 2107.03502] | TimeGrad 为自回归去噪扩散做多变量概率预测；CSDI 为条件分数扩散，用于概率**填补**（也可预测） |
| 共形预测 | 通用后处理 | 给任意点预测器包上覆盖率保证的区间（待核实具体方法选型） |

[经验] 评估概率预测要看**校准**（区间覆盖率是否名副其实）与**锐度**（区间多窄），常用指标是 CRPS / 加权分位数损失；只看 MSE 会把概率模型的价值埋没。指标定义与例子见 [metrics §2](0610_ML_Tasks_TimeSeries_Metrics)。扩散模型推理成本高，需要权衡。

## 6. 表示学习与异常检测

表示学习见 [deep §3.6](0606_ML_Tasks_TimeSeries_Deep)，异常检测的完整专文见 [anomaly](0609_ML_Tasks_TimeSeries_Anomaly)，另见 [deep §3.7](0606_ML_Tasks_TimeSeries_Deep) 与 [ml §3.6](0605_ML_Tasks_TimeSeries_ML)。

### 6.1 表示学习

**TS2Vec** [V: 2106.10466]：在多个层级上做对比学习，得到任意子序列粒度的通用表示，用于分类、预测、异常检测。自监督预训练的价值在**标签少**的场景。

### 6.2 异常检测

- **重构类**：自编码器、LSTM-AE，以重构误差为分数。
- **预测类**：预测下一步，偏差作为异常分数。
- **关联/注意力类**：**Anomaly Transformer** [V: 2110.02642] 提出"关联差异"（association discrepancy）：异常点难以和整条序列建立强关联，而更多关注邻近点；**TranAD** [V: 2201.07284] 用深度 Transformer 加对抗训练与自条件机制处理多变量异常。
- **评测陷阱**：point-adjust 等宽松评估协议会虚高指标；部分基准标签质量有问题。结论上，简单方法往往不输深度模型（如 Audibert et al., *Pattern Recognition* 2022 对 16 种方法的比较，arXiv:2204.01637，本次未核对，待核实；TSB-AD 基准也有类似结论，待核实）。

## 7. 时序基础模型

各模型的设计、预训练数据、评估陷阱与选型见专文 [foundation](0608_ML_Tasks_TimeSeries_Foundation)。

目标：**预训练一次，零样本或少样本用于新数据集**，类似 NLP 的 LLM 范式。

### 7.1 从头预训练的时序基础模型

| 模型 | arXiv | 要点 |
|---|---|---|
| **TimesFM**（Google） | [V: 2310.10688] | 仅解码器（decoder-only）Transformer，以 patch 为输入，大规模真实 + 合成数据预训练，零样本预测 |
| **Chronos**（Amazon） | [V: 2403.07815] | 把数值**缩放并量化为离散 token**，直接用语言模型架构（T5 系）训练，输出概率样本 |
| **Moirai**（Salesforce） | [V: 2402.02592] | "Unified Training of Universal Time Series Forecasting Transformers"：多 patch 尺寸、any-variate 注意力、混合分布输出，依托 LOTSA 大规模数据集 |
| **Lag-Llama** | [V: 2310.08278] | 以滞后特征为 token 的 decoder-only 概率预测基础模型 |
| **Timer** | [V: 2402.02368] | 生成式预训练 Transformer，提出把多种任务统一为序列生成 |
| **Time-MoE** | [V: 2409.16040] | 混合专家（MoE）架构扩展到十亿参数规模 |
| **Sundial** | [V: 2502.00816] | 一族时序基础模型（2025），摘要主打生成式、可输出多种预测样本 |
| **Tiny Time Mixers（TTM）** | [V: 2401.03955] | 小型（MLP-Mixer 系）预训练模型，强调**轻量**零/少样本，适合 CPU/边缘 |
| **MOMENT** | [V: 2402.03885] | 开源的"通用"基础模型家族，覆盖预测、分类、异常检测、填补 |
| **TimeGPT-1**（Nixtla） | [V: 2310.03589] | 商业 API 形式的预测基础模型 |

注：以上一栏仅概括各文标题所示方向和编者了解的主要设计；具体参数量、训练数据规模、基准上的分数请读原文，**本文不转引**。模型版本迭代很快（2025–2026 年多个模型已有更新版本），实际使用前请核对最新发布 [待核实]。

### 7.2 复用 LLM 的路线

- **One Fits All / GPT4TS** [V: 2302.11939]：冻结大部分预训练 GPT-2 参数，仅微调少量层，用于多类时序任务。
- **Time-LLM** [V: 2310.01728]：把时序"重编程"（reprogram）为文本原型，用提示引导冻结的 LLM。
- **质疑**：*Are Language Models Actually Useful for Time Series Forecasting?* [V: 2406.16964] 通过消融实验质疑 LLM 在这类方法中的实际贡献——去掉 LLM 常常不降甚至提升效果，且计算成本小得多。结论：**"借 LLM 做时序"的收益需要谨慎看待**；真正有说服力的是 §7.1 里用时序数据**专门预训练**的模型 [经验，基于该文结论的归纳]。

### 7.3 基础模型何时值得用

[经验]
- 适合：序列短或历史不足（冷启动）、没有精力为每个场景训练模型、需要快速基线。零样本结果是**强的免训练基线**，应与 ETS/ARIMA/LightGBM 一起作为起点。
- 不适合或需谨慎：强业务特定的协变量依赖、领域极特殊的信号（如高频振动波形）、对延迟/资源敏感（大模型）、预训练数据可能与测试集有**泄漏**（评估时务必看模型方的泄漏声明与 GIFT-Eval 的处理方式）。
- 微调通常能进一步提升，但要对比"微调后的基础模型 vs 直接训练的小模型 + 同等调参预算"。

## 8. 评测与基准

### 8.1 常用数据集

| 数据集 | 任务 | 说明 |
|---|---|---|
| ETT（h1/h2/m1/m2） | 长期预测 | 变压器油温，Informer 引入；体量小，可被过拟合 |
| Electricity、Traffic、Weather、Exchange、ILI | 长期预测 | LTSF 论文的标准套件 |
| M3 / M4 / M5 | 预测比赛 | 单变量业务数据（M5 为零售层级销量）；覆盖面比 LTSF 套件更宽（待核实细节） |
| UCR / UEA 档案 | 分类 | ROCKET 系的主要战场 |
| SMD / SMAP / MSL / SWaT / WADI | 异常检测 | 评估协议问题多 |

### 8.2 综合基准

- **TFB** [V: 2403.20150]：覆盖多领域的预测基准，强调**公平比较**，并指出已有基准对传统方法存在"刻板偏见"。
- **GIFT-Eval** [V: 2410.10393]：面向**通用/基础模型**的预测评测基准，覆盖多个领域、频率、预测长度。

### 8.3 评估中的常见陷阱 [经验]

指标的定义、公式与例子单独成文：[metrics](0610_ML_Tasks_TimeSeries_Metrics)。下面只列陷阱清单。

1. **只报 MSE/MAE**：对尺度敏感，跨序列比较请用 MASE、sMAPE（有已知缺陷）、或 CRPS（概率）。
2. **回看窗口不统一**：有的论文给自己调长回看窗口，却给基线用默认值；对比时应对每个方法都搜索回看长度。
3. **"drop-last"类实现细节**：测试集最后不足一个 batch 的样本被丢弃，会导致指标不可比（TFB 讨论了类似的评测不一致，具体表述请读原文）。
4. **数据泄漏**：标准化用了全量统计量、训练/测试窗口重叠、基础模型的预训练集包含测试集。
5. **单次种子**：深度模型方差不小，至少多种子并报均值与标准差。
6. **滚动起点评估**：真实业务应使用 rolling-origin 交叉验证，而不是单一切分。
7. **基准饱和**：ETT 等小数据集上，新模型的差距常落在噪声范围内，不足以支撑"SOTA"结论。

## 9. 选型建议 [经验]

| 场景 | 建议起点 | 理由 |
|---|---|---|
| 序列条数少、单变量、有明显季节 | ETS / ARIMA / Theta（statsforecast） | 便宜、稳、可解释，常不被深度模型显著超越 |
| 大量相关序列（零售、能源节点） | LightGBM 全局模型 + 特征工程；或 N-HiTS / DeepAR / TFT | 全局模型借用跨序列信息；需要协变量时 GBDT/TFT 均可 |
| 需要概率预测/区间 | DeepAR、TFT（分位数）、Chronos 或 Moirai；统计模型自带区间 | 评估 CRPS 与校准 |
| 长期预测、变量多 | DLinear、PatchTST、iTransformer、TimeMixer | 先线性，再看复杂模型是否有增益 |
| 冷启动、历史短 | 时序基础模型零样本（TimesFM / Chronos / Moirai / TTM） | 免训练基线 |
| CPU/边缘部署 | DLinear、N-HiTS、TTM、统计模型 | 小、快 |
| 分类 | ROCKET 系 → 再考虑深度（TimesNet 等） | 基线强且极快 |
| 异常检测 | 统计 + Isolation Forest + 重构/预测类，再上深度；评估协议要严格 | 深度模型优势不稳 |
| 缺失值填补 | 线性插值/Kalman → CSDI 一类生成式 | 先看缺失机制与比例 |

**通用流程** [经验]：
1. 先做**朴素基线**（季节朴素、均值）和**统计基线**（ETS/ARIMA）；
2. 加 **LightGBM** 全局模型；
3. 加一个**线性/MLP 深度模型**（DLinear、N-HiTS）；
4. 试一个**基础模型零样本**；
5. 只有当上述在 rolling-origin 评估下仍有明显差距时，才投入更复杂的 Transformer / 混合模型；
6. 每一步用统一的数据切分、窗口、多个种子与合适指标比较。

## 10. 趋势与开放问题

- **基础模型的真实增益**：零样本是否持续优于调好的局部/全局模型，在不同领域差异大；评估泄漏与基准代表性是核心问题（GIFT-Eval 等在推进）。
- **LLM 的作用**：从"拿 LLM 当骨干"转向"LLM 做解释、推理、与文本协变量融合"；骨干层面的收益被质疑（§7.2）。
- **多变量依赖**：何时建模变量关系有益，缺少统一结论（§4.6）。
- **外生变量与因果**：真实业务的预测很大程度由已知未来事件驱动，纯历史外推模型不够；TimeXer、TFT 属于该方向。
- **效率与可部署性**：小模型（TTM、线性模型）与大模型的取舍；MoE 与 SSM 提供新的算力曲线。
- **评测协议标准化**：TFB、GIFT-Eval 是起点，异常检测领域的评估仍待规范。
- **不确定性与决策**：从概率预测到下游决策（库存、调度）的端到端优化。
