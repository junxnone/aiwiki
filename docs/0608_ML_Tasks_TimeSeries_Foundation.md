## 0. 先看全景

**时序基础模型**（time-series foundation model，TSFM）的目标是：在大规模、多样的时间序列语料上**预训练**一个模型，之后对**从未见过的数据集**直接做**零样本**预测（不更新参数），或少量数据**微调**。这借鉴了自然语言处理里大语言模型的范式。

| 路线 | 做法 | 代表 | 本文章节 |
|---|---|---|---|
| **从头预训练（连续值 patch）** | 序列切成 patch 直接输入 Transformer | TimesFM、Moirai、Timer、Time-MoE、Moirai-MoE、Moirai 2.0、Toto、Sundial | §3.1、§3.3–§3.6 |
| **从头预训练（量化 token）** | 数值缩放并量化为离散 token，沿用语言模型架构与交叉熵 | Chronos、Chronos-2（扩展到多变量与协变量） | §3.2 |
| **轻量预训练** | 小模型（MLP-Mixer 系）为主 | Tiny Time Mixers（TTM）、TSPulse | §3.7 |
| **通用多任务** | 同一模型覆盖预测、分类、异常检测、填补 | MOMENT、Timer、UniTS | §3.7 |
| **概率预测专用** | 以滞后特征为 token、分布输出 | Lag-Llama | §3.4 |
| **商业与领域专用** | 以 API 提供，或针对特定领域数据 | TimeGPT-1、Toto（可观测性数据） | §3.8 |
| **表格基础模型** | 把预测当作表格回归，复用预训练的表格模型 | TabPFN-TS | §3.9 |
| **复用 LLM** | 冻结或少量微调预训练语言模型，加输入输出适配 | One Fits All（GPT4TS）、Time-LLM、LLMTime、TEMPO、LLM4TS | §3.10 |

一句话定位：**零样本基础模型是"几乎免训练的强基线"，而不是必然的赢家**。它在冷启动、历史短、没有精力为每个场景训练模型时很有价值，但必须与调好的经典与机器学习基线在**同一滚动评估**下比较，且要核对**预训练数据泄漏**。

读完本文你应能回答：零样本、少样本、微调有何区别；连续值 patch 与量化 token 是两种什么设计；各主流模型在 tokenization、架构、输出头、多变量/协变量支持上有何不同；为什么"复用 LLM"的路线被质疑；评估基础模型有哪些陷阱；什么时候该用基础模型。

## 1. 基石概念

### 1.1 零样本、少样本与微调

设预训练得到的参数 $\theta^{*}$。对新序列的历史 $\mathbf y_{t-L+1:t}$：

| 模式 | 做法 | 公式 |
|---|---|---|
| **零样本（zero-shot）** | 不更新参数，直接预测 | $\hat{\mathbf y}_{t+1:t+H}=f_{\theta^{*}}\bigl(\mathbf y_{t-L+1:t}\bigr)$ |
| **少样本 / 微调** | 用目标域少量或全部数据更新全部或部分参数 | $\theta'=\arg\min_\theta\sum\ell\bigl(f_\theta(\cdot),\mathbf y\bigr)$，以 $\theta^{*}$ 初始化 |
| **上下文学习（ICL）** | 不更新参数，在输入里放入**多条相关序列示例** | Chronos-2 的"组注意力"、TimesFM-ICF（§3.2、§3.1） |

### 1.2 预训练目标

绝大多数基础模型采用**下一个 patch（或 token）预测**，即自回归式地最大化未来片段的条件分布，或最小化其预测损失：

$$\min_\theta\ \sum_{i}\sum_{t}\ \ell\Bigl(f_\theta\bigl(\mathbf y_{i,\le t}\bigr),\ \mathbf y_{i,t+1:t+P}\Bigr)$$

$i$ 遍历预训练语料中的序列，$P$ 是输出 patch 长度，$\ell$ 取决于输出头（§1.5）。预测长于 $P$ 的 horizon 时，用**滚动解码**：把预测结果拼回上下文，重复 $\lceil H/P\rceil$ 次。MOMENT 等采用**掩码重构**（MOMENT 摘要未写明目标细节，待核实）。

### 1.3 预训练数据

数据是基础模型最关键的一环。各文摘要给出的语料信息（均出自摘要）：

| 模型 | 语料信息（摘要） |
|---|---|
| Chronos | "a large collection of publicly available datasets"，再加**由高斯过程生成的合成数据集**以提升泛化 |
| Moirai | **LOTSA**（Large-scale Open Time Series Archive），超过 **27B** 个观测、**九个领域** |
| Timer | 精心整理的大规模数据，最多 **10 亿**时间点；把异构序列统一为**单序列序列（S3）格式** |
| Time-MoE | **Time-300B**，覆盖 **9 个领域**、超过 **3000 亿**个时间点 |
| Sundial | **TimeBench**，约**一万亿**个时间点，以真实数据为主，辅以合成数据 |
| MOMENT | 自建 **Time series Pile**（公开时间序列合集） |
| Moirai 2.0 | 新语料，**3600 万条序列** |
| Toto | 观测性（可观测性）数据、公开数据集与合成数据的混合，规模为主流 TSFM 语料的 4–10 倍（摘要） |
| TabPFN-TS | **无需时序专用预训练**，复用 TabPFN-v2 |
| TTM | **仅用公开数据集**训练 |

**合成数据**（高斯过程、各类模拟信号）用于补充多样性；GIFT-Eval 提供**不泄漏测试集的预训练语料**，约 2300 亿个数据点（[V]，见 §1.7）。

### 1.4 Tokenization：连续值 patch 与量化 token

**1. 连续值 patch**：把序列切成长为 $P$ 的片段，线性投影成嵌入，直接送入 Transformer：

$$\mathbf e_j=W\,\mathbf y_{(j-1)P+1:jP}+\mathbf b,\qquad j=1,\dots,N,\ \ N=\Bigl\lceil\frac{L}{P}\Bigr\rceil$$

TimesFM、Moirai、Timer、Time-MoE、Sundial 等采用这类（各自的输入输出 patch 设置不同，细节待核实）。

**2. 量化为离散 token（Chronos）**：Chronos（arXiv:2403.07815 [V]）"tokenizes time series values using scaling and quantization into a fixed vocabulary"，并用现成的语言模型架构、**交叉熵损失**训练。其基本做法（依原文印象，细节待核实）：先按序列的尺度缩放（如除以窗口内绝对值的均值），再把缩放后的值映射到 $B$ 个分箱之一：

$$\tilde x_t=\frac{x_t}{s},\ \ s=\frac1L\sum_{i=1}^{L}\lvert x_i\rvert,\qquad \mathrm{tok}_t=\mathrm{bin}(\tilde x_t)\in\{1,\dots,B\},\qquad \mathcal L=-\sum_t\log p_\theta\bigl(\mathrm{tok}_{t+1}\mid\mathrm{tok}_{\le t}\bigr)$$

预测时对 token 采样，反量化并乘回尺度，得到样本路径。**含义**：把回归问题改成**分类**问题，天然给出任意形状的预测分布（含多峰），代价是量化带来精度损失，且 token 序列更长。

**3. 数字文本化（LLMTime）**：*Large Language Models Are Zero-Shot Time Series Forecasters*（arXiv:2310.07820 [V]）把序列编码为**数字字符串**，把预测当作文本的下一个 token 预测，并提出有效的 tokenization 与把 token 离散分布转为连续密度的方法。摘要同时指出：GPT-4 的表现可能比 GPT-3 更差，原因在于**它对数字的分词方式**以及不良的不确定性校准。

### 1.5 输出头与概率预测

| 输出方式 | 说明 | 代表 |
|---|---|---|
| 点预测 | 直接回归 | 部分轻量模型 |
| **分位数** | 同时预测多个分位数，用 pinball 损失 | Moirai 2.0（摘要：quantile forecasting 与 multi-token prediction）、TimesFM 的概率头（待核实） |
| **混合分布** | 输出混合分布参数 $p(y)=\sum_kw_kp_k(y)$ | Moirai（摘要：处理分布性质差异；具体混合分布族待核实） |
| **token 分布** | 对分箱的类别分布采样 | Chronos |
| **参数化分布** | 如 Student-t | Lag-Llama（摘要：概率预测；具体分布待核实） |
| **流匹配样本** | 生成多条预测 | Sundial（TimeFlow Loss，见[生成式篇 §3.6](0607_ML_Tasks_TimeSeries_Generative)） |

分位数的评估指标见 [metrics §2](0610_ML_Tasks_TimeSeries_Metrics)。

### 1.6 架构与稀疏专家

| 架构 | 说明 | 代表 |
|---|---|---|
| 仅解码器（decoder-only） | 因果注意力，next-patch 预测 | TimesFM（摘要：patched-decoder 风格）、Timer、Time-MoE、Lag-Llama、Moirai 2.0（摘要：decoder-only）、Toto（摘要：decoder-only） |
| 掩码编码器 | 双向注意力，掩码重构 | Moirai（摘要：Masked Encoder-based）、MOMENT（待核实） |
| 编码器-解码器 | T5 系 | Chronos（摘要：T5 系，20M–710M 参数） |
| MLP-Mixer | 无注意力 | TTM（摘要：基于轻量 TSMixer，参数量从 1M 起） |

**稀疏混合专家（MoE）**：每个 token 只激活少数几个专家，以较低的推理成本扩大容量：

$$\mathbf y=\sum_{i\in\mathrm{TopK}(g(\mathbf x))}g_i(\mathbf x)\,E_i(\mathbf x)$$

$g$ 是路由器，$E_i$ 是第 $i$ 个专家。Time-MoE（arXiv:2409.16040 [V]）是仅解码器 MoE，摘要称首次把时序基础模型扩展到 **24 亿**参数；Moirai-MoE（arXiv:2410.10469 [V]）用单一输入/输出投影层，把多样时序的建模交给稀疏 MoE。

### 1.7 频率、多变量与协变量

不同序列的频率、变量数和分布差异巨大，是预训练的核心难点。Moirai 摘要列出三项挑战：**跨频率学习**、**任意数量变量**、**大规模数据中的分布差异**。各家的处理不同：

- Moirai（[V]）：用多个输入/输出投影层处理不同频率，并提出"any-variate"机制；
- TimesFM：维护频率嵌入字典（Moirai-MoE 摘要所述）；
- **Moirai-MoE**（[V]）批评这种人为的**频率级专门化**：① 频率并不可靠地反映序列的真实模式（不同频率可有相似模式，相同频率可有不同模式）；② 现实序列固有非平稳，即使在单条序列的短上下文内分布也会变化，频率级专门化粒度太粗；因此改用单一投影层加 token 级稀疏专家；
- **Chronos-2**（arXiv:2510.15821 [V]）：摘要指出现有方法主要关注单变量，限制了对多变量与协变量场景的适用；它提出**组注意力（group attention）**，让一组相关序列（可以是相关的多条序列、同一多变量序列的各变量、或预测任务中的目标与协变量）之间高效共享信息，实现**上下文学习**；这些能力通过在**合成数据**上训练获得，合成数据把多样的多变量结构施加到单变量序列上；
- **TabPFN-TS**（arXiv:2501.02945 [V]）：把预测当作表格回归，天然支持**协变量**；
- **TTM**（[V]）：摘要称它用多层次建模捕捉通道相关并在微调时注入外生信号。

### 1.8 评估基础模型

评估基础模型的核心是**避免泄漏**与**公平比较**：

| 基准 | 摘要给出的要点 |
|---|---|
| **GIFT-Eval**（arXiv:2410.10393 [V]） | 23 个数据集，超过 14.4 万条序列、1.77 亿个数据点，覆盖 7 个领域、10 种频率、多变量输入和短到长期预测长度；提供**不泄漏的预训练数据集**（约 2300 亿数据点）；分析了 17 个基线（统计、深度学习与基础模型） |
| **fev-bench**（arXiv:2509.26468 [V]） | 100 个预测任务、7 个领域，其中 **46 个带协变量**；配套轻量库 fev；用**带自助法置信区间的聚合**报告**胜率**与**技能分数**两个维度，以判断差异是真实改进还是随机波动 |
| Chronos Benchmark II | 见 Chronos-2 摘要（与 fev-bench、GIFT-Eval 并列的三个评测之一，具体内容待核实） |

**评估陷阱** [经验]：

1. **泄漏**：测试数据集或其近亲出现在预训练语料中；应使用模型方声明的"训练内/零样本"划分，或使用 GIFT-Eval 的无泄漏设置；
2. **只在训练语料内的数据集上报告**：Chronos 摘要明确区分了"训练语料内"与"新数据集上的零样本"两种结果；
3. **只比深度模型**，不含调好的 ETS/ARIMA/LightGBM；
4. **聚合方式**：不同数据集尺度不同，需使用相对基线的几何平均或胜率（公式见 [metrics §5.3](0610_ML_Tasks_TimeSeries_Metrics)），并附置信区间（fev-bench 的做法）；
5. **只看点预测**：忽略概率预测与校准。

### 1.9 扩展规律

*Scaling Law for Time Series Forecasting*（arXiv:2405.15124 [V]）摘要：深度学习中"更大的数据集、更复杂的模型、更精细的数据粒度"带来收益的扩展规律在时序预测中受到质疑——更多训练数据确实有助于提升，但**更强的模型并不总胜过较弱的模型，更长的输入窗口也可能损害部分模型**；作者提出同时考虑数据集大小、模型复杂度与**回看窗口**的扩展规律理论来解释这些现象，并经实验验证。含义：**基础模型的收益主要来自数据规模与多样性，而不是单纯增大参数**；Moirai 2.0 摘要也指出模型性能随参数增加会趋于平台，并在更长 horizon 上下降 [V]。

## 3. 各模型详解

> 下面的描述以各文摘要为依据，摘要之外的内部细节一律标"待核实"。具体参数量与得分请读原文，本文不转引。

### 3.1 TimesFM 与 TimesFM-ICF

**TimesFM**（*A decoder-only foundation model for time-series forecasting*，arXiv:2310.10688 [V]）：基于**在大规模时序语料上预训练的 patched-decoder 风格注意力模型**，摘要称其开箱即用的零样本性能在多个公开数据集上接近每个数据集上最先进的**监督**预测模型，并能适应不同的预测历史长度、预测长度和时间粒度。

**TimesFM-ICF**（*In-Context Fine-Tuning for Time-Series Foundation Models*，arXiv:2410.24087 [V]）：设计一个预训练基础模型，推理时可以用**多条相关时间序列示例**作为"提示"来预测目标序列；模型被专门训练去利用上下文窗口中来自多条相关序列的示例，以适应目标域分布。摘要称这样的模型在流行预测基准上明显优于监督深度学习、统计模型及其他时序基础模型，甚至与**在目标域上显式微调**的基础模型相当。**含义**：用"上下文里放示例"代替"更新参数"，是少样本适配的新形态。

### 3.2 Chronos 与 Chronos-2

**Chronos**（arXiv:2403.07815 [V]）：见 §1.4。基于 **T5 系**模型（20M 到 710M 参数），在大量公开数据集加 GP 合成数据上预训练；在含 42 个数据集的综合基准（包含经典局部模型与深度学习方法）上，摘要称：**(a)** 在属于训练语料的数据集上显著优于其他方法；**(b)** 在新数据集上的零样本性能与专门训练的方法"相当、有时更优"。

**Chronos-2**（*From Univariate to Universal Forecasting*，arXiv:2510.15821 [V]）：能在零样本下处理**单变量、多变量和带协变量**的任务；采用**组注意力**机制，使一组序列间共享信息，实现 ICL；靠合成数据训练出多变量结构的建模能力；摘要称在 fev-bench、GIFT-Eval 与 Chronos Benchmark II 三个综合基准上达到最先进，并在带协变量任务上持续优于基线。

### 3.3 Moirai 系列

**Moirai**（*Unified Training of Universal Time Series Forecasting Transformers*，arXiv:2402.02592 [V]）：**掩码编码器**架构的通用预测 Transformer；针对跨频率学习、任意变量数、分布差异三项挑战对传统时序 Transformer 做改进；在 LOTSA（27B 观测、九个领域）上训练；摘要称零样本性能与全样本（full-shot）模型相比具有竞争力或更优。

**Moirai-MoE**（arXiv:2410.10469 [V]）：见 §1.7，用单一输入/输出投影加**稀疏混合专家**，把多样时序的建模交给专家，批评频率级专门化。

**Moirai 2.0**（arXiv:2511.11698 [V]）：**仅解码器**基础模型，在 3600 万条序列的新语料上训练，采用**分位数预测与多 token 预测**。摘要明确说明相对 Moirai 1.0 的简化：以更简单的仅解码器架构、**单一 patch**、**分位数损失**取代掩码编码器训练、多 patch 输入和混合分布输出；消融显示仅解码器骨干与递归多分位数解码贡献最大；摘要称其推理速度是 Moirai 1.0-Large 的两倍、模型小 30 倍且性能更好；同时指出性能随参数量增加趋于平台、在更长 horizon 上下降，因此未来工作聚焦**数据扩展与长 horizon 建模**。

### 3.4 Lag-Llama

**Lag-Llama**（arXiv:2310.08278 [V]）：面向**单变量概率预测**的通用基础模型，基于**仅解码器 Transformer**，以**滞后值（lags）作为协变量**；在多领域大语料上预训练，摘要称零样本泛化能力强，并在对未见数据集的小比例数据上微调后取得最先进性能，在平均意义上成为最佳通用模型。

### 3.5 Timer 与 Time-MoE

**Timer**（*Generative Pre-trained Transformers Are Large Time Series Models*，arXiv:2402.02368 [V]）：整理高达 10 亿时间点的预训练数据，把异构序列统一为**单序列序列（S3）格式**，采用 **GPT 风格**架构；把**预测、填补、异常检测**统一为生成任务；通过 **next token prediction** 生成式预训练，再适配下游。

**Time-MoE**（arXiv:2409.16040 [V]）：**仅解码器、自回归**的稀疏 MoE 家族，支持灵活的预测长度和上下文长度；在 **Time-300B**（300B+ 时间点、9 个领域）上预训练；摘要称**首次**把时序基础模型扩展到 **24 亿**参数，并通过只激活部分网络降低推理成本。

### 3.6 Sundial

**Sundial**（arXiv:2502.00816 [V]）：见[生成式篇 §3.6](0607_ML_Tasks_TimeSeries_Generative)。**TimeFlow Loss**（基于流匹配）让 Transformer 在**连续值**序列上原生预训练，无需离散 tokenization；以 TimeBench（约一万亿时间点）预训练；可**生成多条可能预测**，缓解模式坍塌；摘要称在点预测与概率预测基准上最先进，且可在几毫秒内给出零样本预测。

### 3.7 轻量模型与通用多任务模型

**TTM**（Tiny Time Mixers，arXiv:2401.03955 [V]）：**紧凑模型（1M 参数起）**，基于轻量 **TSMixer** 架构，**仅用公开数据集**训练；摘要提到的创新包括**自适应 patching**、**多分辨率采样**与**分辨率前缀微调**，以在极小容量下处理不同分辨率的预训练；多层次建模用于捕捉通道相关并在微调时注入外生信号；摘要称零/少样本预测超出已有基准 4–40%，同时大幅降低计算需求，并可在 CPU 上运行。

**TSPulse**（arXiv:2505.13033 [V，仅核对标题]）：标题表明是"带解耦表示的微型预训练模型，用于快速时序分析"，内部细节待核实。

**MOMENT**（arXiv:2402.03885 [V]）：**开源通用**时序基础模型家族；整理 **Time series Pile**，针对时序特有挑战实现多数据集大规模预训练；并设计了**有限监督场景**下评测基础模型的基准；摘要称在少量数据与任务特定微调下，预训练模型即有效。

**UniTS**（arXiv:2403.00131，仅核对标题）：标题表明为统一多任务时序模型，细节待核实。

### 3.8 商业与领域专用

**TimeGPT-1**（arXiv:2310.03589 [V]）：摘要称其为"the first foundation model for time series"，能对预训练时未见的多样数据集生成准确预测，零样本推理在性能、效率与简便性上突出。以 API 形式提供（凭记忆，摘要未写，待核实）。**使用商业 API 前要确认数据是否离开自己的环境、是否符合合规要求** [经验]。

**Toto**（*This Time is Different: An Observability Perspective on Time Series Foundation Models*，arXiv:2505.14766 [V]）：151M 参数、现代仅解码器架构，加上针对**多变量可观测性时序**特点的结构创新；预训练语料混合了可观测性数据、公开数据集与合成数据，规模是主流基础模型的 4–10 倍；同时提出 **BOOM** 基准（3.5 亿观测、2807 条真实序列），数据来自 Datadog 自身遥测与内部指标；权重、推理与评测脚本开源。**含义**：领域专用语料可能给领域内数据带来优势，也提示**通用基准未必代表你的领域** [经验]。

### 3.9 表格基础模型：TabPFN-TS

**TabPFN-TS**（*From Tables to Time*，arXiv:2501.02945 [V]）：把预测当作**表格回归**，把轻量的**时间特征化**与预训练的 TabPFN-v2 结合；摘要称**无需时序专用预训练**，天然支持**单变量与带协变量**预测；只有 11M 参数，在 GIFT-Eval 与 fev-bench 的**协变量预测**上达到最先进、在单变量预测上有竞争力，并分析了模型如何理解时间结构。**含义**：协变量重要的场景里，"特征化 + 预训练的通用表格模型"是与专门时序基础模型并行的路线（对比[机器学习篇 §5.4](0605_ML_Tasks_TimeSeries_ML)）。

### 3.10 复用大语言模型的路线及其质疑

#### 做法

| 方法 | 做法（摘要） |
|---|---|
| **One Fits All / FPT**（arXiv:2302.11939 [V]） | **Frozen Pretrained Transformer**：不改动预训练语言（或视觉）模型的自注意力与前馈层，仅微调（输入输出适配等）；摘要称在所有主要时序任务上可达到相当或最先进的性能，并从理论与实验上分析自注意力的行为 |
| **Time-LLM**（arXiv:2310.01728 [V]） | **重编程框架**：把输入时序用**文本原型**重编程后送入冻结的 LLM 以对齐两种模态；并提出 **Prompt-as-Prefix（PaP）** 丰富输入上下文、引导重编程后的表示的转换 |
| **LLMTime**（arXiv:2310.07820 [V]） | 把时序编码为数字字符串，视为文本的下一 token 预测；摘要称 GPT-3、LLaMA-2 零样本外推的水平可与专门训练的时序模型相当或更优；并指出这源于 LLM 对多峰分布的自然表示，以及对简单性与重复性的偏置；还能处理缺失（用非数字文本）并接受文本旁路信息 |
| **TEMPO**（arXiv:2310.04948）、**LLM4TS**（arXiv:2308.08469）、**S²IP-LLM**（arXiv:2403.05798）、*Time Series Forecasting with LLMs: Understanding and Enhancing Model Capabilities*（arXiv:2402.10835） | 以上均已核对标题与编号 [V]；内部机制未读，待核实 |

结构通常是：$\hat{\mathbf y}=W_o\ \mathrm{LLM}_{\text{frozen}}\bigl(W_i\ \mathrm{patches}(\mathbf y)\bigr)$，$W_i,W_o$ 为可学习的输入投影与输出头。

#### 质疑

*Are Language Models Actually Useful for Time Series Forecasting?*（arXiv:2406.16964 [V]）：对三种近期流行的基于 LLM 的预测方法做消融，摘要结论是：**移除 LLM 或用基本注意力层替换，预测性能不下降，多数情况下甚至更好**；并发现尽管计算成本高昂，**预训练 LLM 并不优于从头训练的模型、没有表示时序中的序列依赖、也无助于少样本场景**；patching 和注意力结构的时序编码器表现与基于 LLM 的预测器相近。

**含义**：LLM 作为"时序骨干"的收益需谨慎看待；真正有说服力的是在**时序数据上专门预训练**的模型（§3.1–§3.7）以及 LLM 用于**文本旁路信息、解释**的场景 [经验，基于上述摘要的归纳]。

### 3.11 基础模型综述

*Foundation Models for Time Series Analysis: A Tutorial and Survey*（arXiv:2403.14735 [V]）采用**以方法论为中心**的分类，梳理时序基础模型的模型架构、预训练技术、适配方法与数据模态等关键要素，并强调背后的机制。

## 5. 发展趋势

下面各条分"事实"（基于上述已核对摘要）与"判断"（编者 [经验]，需持续观察）。

### 5.1 从单变量到协变量与多变量

- **事实**：Chronos-2、TabPFN-TS 的摘要都强调协变量；fev-bench 专门包含 46 个带协变量的任务；Moirai 早期就提出 any-variate；TTM 摘要提到注入外生信号。
- **判断**：真实业务的预测很大程度由已知未来事件驱动，**协变量支持**会成为基础模型能否落地的分水岭 [经验]。

### 5.2 简化与"小而快"

- **事实**：Moirai 2.0 的标题与摘要强调"less is more"，用更简单的仅解码器、单 patch 与分位数损失取代更复杂的设计，更小更快；TTM 以 1M 参数起、可在 CPU 运行；Moirai 2.0 同时指出性能随参数量趋于平台。
- **判断**：数据规模与多样性比参数量更重要，**效率**成为竞争点 [经验]。

### 5.3 上下文学习与免微调适配

- **事实**：TimesFM-ICF 和 Chronos-2 都用上下文中的相关序列作适配。
- **判断**："提示式适配"可能取代部分微调场景，降低使用门槛 [经验]。

### 5.4 概率输出与连续值生成

- **事实**：Chronos 的 token 分布、Moirai 2.0 的分位数、Sundial 的流匹配样本，代表三种不同的概率输出路线。
- **判断**：概率预测会成为基础模型的标配，**校准**需要单独评估，共形外壳（[经典篇 §3.15](0604_ML_Tasks_TimeSeries_Classical)）可叠加 [经验]。

### 5.5 领域专用基础模型

- **事实**：Toto 针对可观测性数据并配套 BOOM 基准；摘要强调其语料规模为主流的 4–10 倍。
- **判断**：通用模型在专业领域（运维、能源、医疗）未必最优，领域语料与领域基准会越来越重要 [经验]。

### 5.6 评估：无泄漏与统计严谨

- **事实**：GIFT-Eval 提供不泄漏的预训练数据；fev-bench 用自助法置信区间和胜率/技能分数。
- **判断**：**无泄漏、带置信区间、含协变量任务**将成为评测的基本要求；在此之前，宣称"基础模型优于所有方法"的结论应谨慎对待 [经验]。

### 5.7 对复用 LLM 路线的重新评估

- **事实**：消融研究（[V] 2406.16964）表明去掉 LLM 常不降性能；LLMTime 摘要则显示在适当 tokenization 下 LLM 零样本表现可观，同时指出 GPT-4 的数字分词问题。
- **判断**：结论取决于具体方法与评估；**LLM 的更稳妥价值**可能在于文本旁路信息、解释与交互，而非充当时序骨干 [经验]。

## 6. 实践建议 [经验]

**什么时候考虑基础模型**

| 场景 | 建议 |
|---|---|
| 序列短、历史少（冷启动）、没有精力为每个场景训练模型 | 基础模型零样本是很好的起点 |
| 有重要协变量（价格、促销、天气） | 优先看支持协变量的方案：Chronos-2、TabPFN-TS、TFT、LightGBM；不要默认零样本单变量模型 |
| 序列条数极多、资源有限 | 小模型（TTM）或加速的统计模型 + 全局模型 |
| 领域特殊（高频振动波形、运维指标等） | 先在你的数据上做滚动评估；考虑领域专用模型或微调 |
| 对延迟、成本敏感 | 小模型或统计模型；避免大模型逐条推理 |
| 数据不能出内网 | 避免商业 API；用可本地部署的开源模型 |

**推荐流程**

1. 先做经典、机器学习与线性/MLP 深度基线（[经典篇 §6](0604_ML_Tasks_TimeSeries_Classical)、[机器学习篇 §6](0605_ML_Tasks_TimeSeries_ML)、[深度篇 §6](0606_ML_Tasks_TimeSeries_Deep)）；
2. 跑 1–2 个基础模型的**零样本**，使用与基线相同的**滚动起点**切分；
3. 核对**泄漏**：该模型的预训练语料是否含你的评测数据（或其近亲）；
4. 指标同时看点预测与概率预测（[metrics](0610_ML_Tasks_TimeSeries_Metrics)），并用相对基线的几何平均或胜率聚合；
5. 差距明显时再考虑**微调**，并与"同等调参预算的小模型"比较；
6. 最终可做**集成**：基础模型 + ETS/ARIMA/LightGBM 的平均，常比单个更稳（[经典篇 §3.13](0604_ML_Tasks_TimeSeries_Classical)）。

**常见错误**

- 在训练语料内的数据集上评测并声称"零样本"；
- 只与弱基线或未调参的模型比较；
- 忽略预测区间的校准；
- 把"基准上最优"当作"你的数据上最优"；
- 忽略推理成本与部署约束；
- 用商业 API 处理敏感数据而未确认合规。

**工具**（版本与接口以官方文档为准，待核实）

| 用途 | 说明 |
|---|---|
| 模型权重 | 多数开源模型通过 Hugging Face 发布（MOMENT、Toto 摘要给出 Hugging Face 路径；Moirai 摘要给出 uni2ts 仓库） |
| 评测 | GIFT-Eval、fev-bench 的配套库 fev（[V] 摘要） |

## 7. 基础模型路线的局限

- **泄漏与评估不统一**：预训练语料与测试集的重叠难以完全排除；
- **协变量与多变量支持不一**：多数早期模型只吃单变量历史；
- **领域差异**：通用模型在专业领域未必最优；
- **概率预测的校准**：需单独检验；
- **推理成本**：大模型逐条推理对延迟与资源敏感；
- **可解释性弱**：不如状态空间/ETS 的分量语义清晰；
- **版本迭代快**：结论容易过时，需关注最新版本与第三方评测；
- **LLM 复用路线收益存疑**（[V] 2406.16964）。

不过零样本基础模型作为**免训练基线**的价值是明确的：它们应与 ETS、Theta、季节朴素并列，成为任何新方法的必比对象。
