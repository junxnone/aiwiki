# TimeGPT-1

TimeGPT-1（论文标题 "TimeGPT-1"，作者 Azul Garza、Cristian Challu、Max Mergenthaler-Canseco，Nixtla，arXiv:2310.03589；本文依据 v3，2024-05-27）是一个预测基础模型。论文自称 "the first foundation model for time series"：在大规模公开时间序列上预训练一个 Transformer，之后对训练时没见过的序列直接做零样本（zero-shot）预测，也可以微调（fine-tuning）；预测区间用 conformal prediction 得到。模型以 Python SDK 与 REST API 形式提供（论文附录写明当时为 private beta），论文没有公开权重、训练数据清单，架构也只有一段概述。

一句话概括：把"为每条序列（或每个数据集）训练一个模型"变成"调用一次预训练模型的预测接口"；代价是模型本身是闭源黑盒，论文中的可核验信息很少。

在本系列中的位置：它与 Lag-Llama、TimesFM、Chronos、Moirai 等基础模型同属"预训练 + 零样本预测"路线，总览见 [基础模型篇](/0608_ML_Tasks_TimeSeries_Foundation) 与 [时间序列总览](/0603_ML_Tasks_TimeSeries)。这些模型本篇只写名字。

先说读法：这篇论文只有 12 页（含附录与参考文献），实验部分只有一张主表、一张分布图、一张微调曲线、一段速度对比。下面凡是"论文没写"的地方都明确写出，不做补全；论文之外的内容标 [经验]、[解读] 或 [待核实]。

## 解决什么问题 / 动机

论文的论证链条如下（以下为论文观点，不等于已被验证的事实）：

1. 预测社区对深度学习是否真的优于统计方法存在分歧；有人指出一些深度模型的创新并未兑现承诺，也有工业界报告深度方法改善了结果。
2. 论文把怀疑归因于两点：评测设置错位或定义不清；以及公开时间序列数据集的规模和体量不足，不像 ImageNet 之于视觉，难以让深度方法发挥。
3. 因此论文要展示：更大、更多样的数据能让更复杂的模型表现更好；并引用 scaling law 方面的已有工作（Kunz et al., 2023；Brown et al., 2020）作为支持，用来解释为什么在小数据集上简单模型可能优于 Transformer。
4. 实际收益的主张：把预测流程"缩减为推理一步"，不再需要数据处理、训练、模型选择的完整流水线。

[解读] 这里的"基础模型"含义偏工程：一个通用的、免训练的预测函数。论文自己对"基础模型"的定义是"在大数据集上预训练、之后针对具体任务微调的大规模模型"（文献综述一节）。

## 问题设定

预测函数记为 $f_\theta:\mathcal X\to\mathcal Y$，其中输入空间 $\mathcal X=\{\mathbf y_{[0:t]},\mathbf x_{[0:t+h]}\}$，输出空间 $\mathcal Y=\{\mathbf y_{[t+1:t+h]}\}$；$h$ 是预测步长，$\mathbf y$ 是目标序列，$\mathbf x$ 是外生协变量（注意协变量下标到 $t+h$，即包含未来 $h$ 步，也就是需要已知的未来协变量，如日历、事件）。预测任务就是估计条件分布：

$$\mathbb P\big(\mathbf y_{[t+1:t+h]}\mid \mathbf y_{[0:t]},\mathbf x_{[0:t+h]}\big)=f_\theta\big(\mathbf y_{[0:t]},\mathbf x_{[0:t+h]}\big)$$


其中：$\mathbb P(\cdot\mid\cdot)$ 是条件概率分布；$\mathbf y_{[t+1:t+h]}$ 是未来 $h$ 步目标；$\mathbf y_{[0:t]}$ 是历史目标；$\mathbf x_{[0:t+h]}$ 是外生协变量（含未来 $h$ 步已知部分）；$f_\theta$ 是预测函数，$\theta$ 是模型参数。

迁移学习：在源数据集 $D_s=\{(\mathbf X,\mathbf y)\mid \mathbf X\in\mathcal X,\ \mathbf y\in\mathcal Y\}$ 上预训练，用来提升在目标数据集 $D_t$ 上的表现。论文考虑两种：

- 零样本：预训练模型直接用于新任务，不在新数据上重新训练参数 $\theta$；
- 微调：以预训练参数为起点，在新数据上继续训练。

## 核心思想与结构

核心思想只有一句：在"迄今最大的公开时间序列集合"上训练一个大 Transformer，借助 scaling law 的直觉让它泛化到新数据。论文结构图（Figure 2/3）的大意如下（ASCII 示意为本文自绘）：


下图概括 TimeGPT-1 的训练与推理流程。

```
训练:  多领域训练集 (金融/电力/网络流量/零售/旅游/IoT/医疗/交通/经济)
          |
          v
   [ Transformer 编码器-解码器 ]  (示意图中每层: 多头注意力 + CNN + Add&Norm)
          |
推理:  历史值 y[0:t] + 外生变量/事件 x  -->  模型  -->  预测 y[t+1:t+h]
                                                       + conformal 预测区间
```

图中：训练阶段使用来自金融、电力、网络流量等多个领域的训练集，训练一个 Transformer 编码器-解码器（每层含多头注意力、CNN 与 Add & Norm）；推理阶段输入历史值与外生变量/事件，模型输出预测，并给出 conformal 预测区间。

论文文字描述的架构（5.1 节）：

- 基于 Vaswani et al. 2017 的自注意力 Transformer；
- 输入一个历史窗口，加"局部位置编码"（local positional encoding）；
- 编码器-解码器结构，多层，每层有残差连接与 layer normalization；
- 最后一个线性层把解码器输出映射到预测窗口维度；
- 论文强调：不是基于现有 LLM，而是专门面向时间序列、以最小化预测误差为目标训练的。

结构图中编码器和解码器的子块里画有 "CNN" 模块（与 Add & Norm 交替）；正文没有解释这个 CNN 的细节。

## 训练

- 数据：超过 1000 亿数据点，来自金融、经济、人口、医疗、天气、IoT 传感器、能源、网络流量、销售、交通、银行等领域；论文称序列含多种季节性、不同长度的周期、多种趋势，也有噪声和异常值；多数序列保持原始形态，处理仅限格式标准化与补缺失值。
- 硬件与优化：多天训练，NVIDIA A10G GPU 集群，PyTorch，Adam，学习率衰减（降到初始值的 12%）；做了广泛的超参探索，观察到与 Brown et al. 2020 一致的现象，即更大的 batch、更小的学习率有利。
- 论文没有说训练了多少步、多少 epoch、总计算量。

## 推理与不确定性（conformal prediction）

推理时，模型拿到目标序列的历史值（以及可选的外生变量），一次前向给出 $h$ 步预测，不更新参数。

区间估计（5.4 节）的论文原文要点：

- conformal prediction 是非参数框架，可以给出预先设定覆盖率的预测区间（引用 Shafer & Vovk 2008；Stankeviciute et al. 2021）；
- 不要求严格的分布假设，与模型和时间序列领域无关；
- 对新序列推理时，在"最新可用数据"上做滚动预测（rolling forecasts），估计模型在这条目标序列上的预测误差；图 3 的说明写作 "conformal predictions based on historic errors"。

论文没写的部分：滚动了多少个窗口、用什么非一致性分数、取哪个分位数、是否对多步预测的每个 horizon 分别校准，也没有报告区间覆盖率或区间宽度的实验。论文的实验部分只评估点预测（rMAE、rRMSE）。

下面是通用 split conformal 的做法，用来帮助理解"用历史误差构造区间"这个想法 [解读]（并非论文确认的具体算法）：对 $n$ 个校准窗口，记绝对误差 $e_j=\lvert y_j-\hat y_j\rvert$，对目标覆盖率 $1-\alpha$，取

$$q=\text{第 }\lceil (n+1)(1-\alpha)\rceil\text{ 小的 }e_j,\qquad \big[\hat y-q,\ \hat y+q\big]$$


其中：$n$ 是校准窗口数；$e_j$ 是第 $j$ 个校准窗口的绝对误差；$\alpha$ 是允许的错误率（$1-\alpha$ 为目标覆盖率）；$q$ 是第 $\lceil (n+1)(1-\alpha)\rceil$ 小的误差，作为区间半宽；$\hat y$ 是点预测，区间为 $[\hat y-q,\hat y+q]$。

自拟示意例子（非论文数据）：$n=5$，误差为 $2,5,3,4,1$，$\alpha=0.2$。$\lceil 6\times 0.8\rceil=\lceil 4.8\rceil=5$，取第 5 小的误差，即 $q=5$；若点预测 $\hat y=100$，则区间为 $[95,105]$。

## 实验与结论

### 设置（论文原文）

- 测试集：超过 30 万条时间序列，来自金融、网络流量、IoT、天气、需求、电力等领域，称均未在训练中出现。论文没有给出这些数据集的名字。
- 评估方式：只在每条序列的"最后一个预测窗口"上评估。论文认为经典的切分（即使交叉验证）不足以评估基础模型，因为基础模型的特点是能预测完全新的序列。
- 预测步长：月度 12，周度 1，日度 7，小时 24（脚注 4 说明未来工作应扩展和丰富该测试集）。
- 基线：Baseline 组（ZeroModel、HistoricAverage、SeasonalNaive）；统计组（Theta、DOTheta、ETS、CES、ADIDA、IMAPA、CrostonClassic）；机器学习（LGBM）；深度学习（LSTM、DeepAR、TFT、NHITS）。Prophet 与 ARIMA 因"计算需求过高、训练时间过长"被排除。
- 基线与统计模型：在测试集的每条序列上单独训练，只用最后一个预测窗口之前的历史。机器学习和深度学习：每个频率训练一个全局模型，使用该频率测试集内的所有序列。
- 指标：rMAE 与 rRMSE，相对 Seasonal Naive 归一化，公式（论文式 (2)，$n$ 条序列、步长 $h$）：

$$rMAE=\frac{\sum_{i=1}^{n}\sum_{t=1}^{h}\lvert y_{i,t}-\hat y_{i,t}\rvert}{\sum_{i=1}^{n}\sum_{t=1}^{h}\lvert y_{i,t}-\hat y^{base}_{i,t}\rvert}$$

$$rRMSE=\frac{\sum_{i=1}^{n}\sqrt{\sum_{t=1}^{h}\big(y_{i,t}-\hat y_{i,t}\big)^{2}}}{\sum_{i=1}^{n}\sqrt{\sum_{t=1}^{h}\big(y_{i,t}-\hat y^{base}_{i,t}\big)^{2}}}$$


其中：$n$ 是序列条数；$h$ 是预测步长；$y_{i,t}$ 是第 $i$ 条序列第 $t$ 步的真实值；$\hat y_{i,t}$ 是模型预测；$\hat y^{base}_{i,t}$ 是基线（Seasonal Naive）预测；rMAE 用绝对误差之和相对基线归一，rRMSE 用每条序列的均方根误差之和相对基线归一，二者都小于 1 表示优于基线。

注意这是"先对全数据集求和再相除"的全局归一化（论文称在每个完整数据集上全局应用归一化），因此 Seasonal Naive 恒为 1.000，小于 1 表示优于 Seasonal Naive。

[解读] 周度 $h=1$ 时，$\sqrt{(y-\hat y)^2}=\lvert y-\hat y\rvert$，所以周度的 rMAE 与 rRMSE 在表中完全相同（表中确实如此）。

## 优缺点与局限

论文自述的局限：

- 论文承认存在许多重要局限和开放问题，未来工作包括融入底层过程知识的 informed forecasting、时间序列 embedding / 相似度度量，以及分类、多模态基础模型等方向；
- 测试集需要扩展和多样化（脚注 4）；
- 在数据集或算力有限时，简单模型可能更合适（论文自己的讨论）。

[经验] 使用与复现层面的问题：

- 复现性：权重、训练数据清单、测试集名单都没有公开，外部无法复现 Table 1，也无法检查训练集与测试集是否有重叠；API 背后的模型版本可能随时间变化 [待核实]。
- 评测面窄：每条序列只评一个最后窗口，周度只预测 1 步；由式 (2) 的形式可见，rMAE 是"总误差之比"，绝对误差大的序列权重更大 [解读]。
- 基线设置不透明：全局模型的调参、窗口长度、训练轮数未说明；NHITS 的论文作者与本文作者有重叠（见论文参考文献：Challu et al., 2023）[解读]。
- 数据与合规：调用 API 意味着数据要发给服务方，企业场景要确认合规 [经验]。
- 对其评测公平性的争议属于论文之外的内容：常见的质疑方向是闭源 API 难以排除测试序列出现在训练数据中、基线调参不透明、以及后续独立评测是否复现了论文排名。这些质疑的具体出处与数字均 [待核实]，本文不引用具体数字；基础模型篇对它的描述同样标注"待核实"，见 [基础模型篇](/0608_ML_Tasks_TimeSeries_Foundation)。

与传统"一个数据集训练一个模型"的区别：TimeGPT 的卖点是推理即预测，省去训练与选模；与 N-BEATS、N-HiTS（以及 [DeepAR](/0625_ML_Tasks_TimeSeries_Deep_DeepAR)、[TCN](/0626_ML_Tasks_TimeSeries_Deep_TCN)）等深度预测模型相比，是否更准要看 Table 1 的名次，不是全面领先。
