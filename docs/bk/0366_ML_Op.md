Op（Operator，算子）是神经网络计算图里的基本计算单元：模型 = 一张由 Op 作为节点、Tensor
作为边的有向图。训练框架（PyTorch/TensorFlow）、交换格式（ONNX）和推理引擎（OpenVINO/TensorRT/oneDNN）都围绕
Op 集合定义自己的"词汇表"，同一个数学 Op 在不同层面有不同的名字和实现，本文给出常见 Op 的分类索引，各 Op
的目的、用法与不同实现见对应专文。

## Op 的三个层面

| 层面     | 例子                                          | 关注点           |
| ------ | ------------------------------------------- | ------------- |
| 数学定义   | $y = Wx + b$                                | 语义、梯度         |
| 框架 API | `torch.nn.Linear` / `F.linear`              | 参数、默认值、训练行为   |
| 推理实现   | oneDNN inner\_product、cuBLAS GEMM、融合 kernel | 内存布局、精度、融合、速度 |

  - 同一个 Op 的实现差异（朴素循环 / GEMM / Winograd /
    FFT、融合与否、FP32/FP16/INT8）是模型部署性能的主要来源。
  - 计算图优化的本质：把一串小 Op 融合成一个大 Op（如 Conv+BN+ReLU），或消除只改变布局的
    Op（Transpose/Reshape）。

## 按计算特性理解 Op

| 类型            | 代表                              | 性能瓶颈      | 优化方向                                    |
| ------------- | ------------------------------- | --------- | --------------------------------------- |
| Compute-bound | MatMul、Conv                     | 算力（FLOPs） | 库（oneDNN/cuDNN）、低精度（FP16/INT8）、Winograd |
| Memory-bound  | Elementwise、Norm、Softmax、Reduce | 访存带宽      | 算子融合、减少读写次数                             |
| Layout-only   | Reshape、Transpose               | 数据搬运      | 消除、下沉、改用 stride 视图                      |

## 典型融合模式

  - `Conv + BN (+ ReLU)`：BN 在推理时折叠进卷积权重，见
    [BatchNorm](0614_ML_Op_Norm_BatchNorm)。
  - `MatMul + Add(bias) + 激活`：Linear 的 post-op 融合，见
    [Linear](0612_ML_Op_Linear)。
  - `MatMul + Softmax + MatMul`：FlashAttention 一类的融合 Attention，见
    [SDPA](0499_ML_Attention_SDPA)。
  - 一串 Elementwise：合成一个 kernel，见 [Elementwise](0620_ML_Op_Elementwise)。
