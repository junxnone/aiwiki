# CV 计算机视觉

## 什么是计算机视觉

计算机视觉（Computer
Vision，CV）要解决的问题可以用一句话概括：**让计算机像人眼+大脑一样，从图像/视频里"看懂"信息，而不只是存一堆像素数字**。

人看一张照片，几乎不假思索就能说出"这是一只猫""它在沙发上""画面有点暗"；但对计算机来说，一张照片一开始只是一个巨大的数字矩阵（每个像素是几个
0-255
的数），计算机视觉研究的就是怎么从这堆数字里，一步步算出"边缘在哪""这是什么形状""这块区域和那块区域是不是同一个物体""图里有没有猫"这类人类看一眼就懂、但计算机需要专门算法才能得到的信息。

日常生活里已经到处都是计算机视觉的应用，只是大多数人没意识到：

  - 手机解锁时的人脸识别；
  - 扫一扫就能识别的二维码/条形码；
  - 拍照时手机自动给人脸框一个方框（人脸检测）；
  - 自动驾驶汽车识别车道线、红绿灯、行人；
  - 工厂流水线上自动挑出有瑕疵的零件（见 [工业异常检测](0277_ML_Tasks_Image_Anomaly)）；
  - 拍文件/车票自动识别出文字（OCR，见 [OCR](0200_ML_Tasks_Image_OCR)）。

这些场景表面上五花八门，但拆解到底层，用到的都是本页要介绍的这一整套"从图像里提取信息"的基础技术。

## 计算机视觉的两条脉络

这个领域大致分成两个阶段/两条技术路线，了解这个划分，才能理解本 Wiki
里"CV"、"OpenCV"、"机器学习/深度学习"这几个顶层分类为什么要分开放：

|             | 传统计算机视觉（本页覆盖）                                   | 基于深度学习的计算机视觉                               |
| ----------- | ----------------------------------------------- | ------------------------------------------ |
| 核心思路        | 人工设计特征和规则（"先验知识驱动"）——比如明确告诉算法"边缘就是像素灰度值变化剧烈的地方" | 让神经网络自己从海量数据里学出什么是"猫"、什么是"缺陷"，不需要人工告诉它具体规则 |
| 典型技术        | 二值化、边缘检测、角点/特征点、霍夫变换、图像分割                       | CNN/Transformer 做分类、检测、分割、OCR、异常检测等        |
| 优点          | 可解释性强，不需要大量标注数据，计算量小                            | 复杂场景下精度通常远超传统方法                            |
| 局限          | 规则是人定的，遇到规则没覆盖到的场景容易失效                          | 需要大量数据和算力，可解释性差                            |
| 本 Wiki 对应位置 | 本页及其子页面；工程实现用 [OpenCV](0105_OpenCV)             | [机器学习/深度学习](0416_ML) 下的各个具体任务页面            |

**重要认知**：这两条路线不是"新的淘汰旧的"关系，而是互补的——实际项目里经常是先用传统方法做预处理/候选区域提取（计算量小、速度快），再用深度学习模型做最终判断；传统方法里的很多概念（边缘、特征、直方图）在理解深度学习模型"学到了什么"时同样是重要的直觉基础。所以即使你的目标是做深度学习方向的
CV 工作，也建议先过一遍本页这些经典算法，而不是直接跳过去。

## 入门路线图

建议按下面的顺序学习，而不是在左侧目录里随便点——目录是按字母/主题归档的，不代表学习的先后顺序：

### 第 0 步：图像基础概念（如果还不熟悉）

在学任何算法之前，先搞清楚"图像在计算机里到底是什么"：像素、分辨率、色彩空间（RGB/灰度）这些概念见 [Media](0417_Media)
下的图像相关页面；如果打算用 OpenCV 写代码，`Mat` 这个核心数据结构见 [OpenCV
数据结构](0364_OpenCV_data)。

### 第 1 步：像素级操作——怎么从"一堆数字"变成"有结构的信息"

| 顺序 | 主题                                                     | 解决什么问题                                        |
| -- | ------------------------------------------------------ | --------------------------------------------- |
| 1  | [Thresholding 二值化](0099_CV_BIN)                        | 最简单的"分前景背景"手段：设一个阈值，亮的算一类、暗的算另一类              |
| 2  | [Histogram Equalization 直方图均衡](0100_CV_HE)             | 图片太暗/太亮/对比度差时，怎么用统计手段把细节"拉"出来                 |
| 3  | [边缘](0065_CV_Edge)（含 [Canny 边缘检测](0101_CV_Edge_Canny)） | 怎么找到"亮度剧烈变化"的地方——边缘往往对应物体的轮廓                  |
| 4  | [Structure Tensor 结构张量](0070_CV_StructureTensor)       | 比单纯边缘检测更进一步：不仅知道"这里有变化"，还能分析变化的方向性，是角点检测的数学基础 |

### 第 2 步：从"点/边"到"有意义的特征"

| 顺序 | 主题                                                                                                         | 解决什么问题                                          |
| -- | ---------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| 5  | [图像特征](0064_CV_Feature)（[Harris Corner](0067_CV_Feature_Harris)、[Moravec Corner](0066_CV_Feature_Moravec)） | 找到图像里"特别"的点（角点）——这些点在不同图像间更容易被重新找到，常用于图像匹配/追踪   |
| 6  | [SIFT 尺度不变特征变换](0069_CV_Feature_SIFT)                                                                      | 进阶版特征点：即使图像被缩放、旋转、光照变化，依然能稳定匹配——拼图全景图、物体识别早期都靠它 |
| 7  | [Blob Detection](0068_CV_Blob)                                                                             | 找图像里"一整块"和周围明显不同的区域（斑点），而不只是一个点                 |

### 第 3 步：从"特征"到"形状/区域"

| 顺序 | 主题                                                                           | 解决什么问题                                        |
| -- | ---------------------------------------------------------------------------- | --------------------------------------------- |
| 8  | [Hough Transform 霍夫变换](0071_CV_HoughTransform)                               | 已经检测出边缘/点之后，怎么从一堆零散的点里"拟合"出直线、圆这类规则形状         |
| 9  | [Traditional Image Segmentation 传统图像分割](0158_CV_TIS)                         | 把图像切分成若干个有意义的区域（而不只是找边缘/角点），回答"这块和那块是不是同一个物体" |
| 10 | [Nearest Neighbor interpolation 最近邻插值](0397_CV_NearestNeighborInterpolation) | 图像缩放/几何变换时怎么给新像素赋值，是理解各种插值算法（双线性、双三次）的最简单起点   |

### 第 4 步：综合应用与工程实践

| 顺序 | 主题                                     | 解决什么问题                                                                                                    |
| -- | -------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 11 | [Traditional OCR 传统字符识别](0199_CV_TOCR) | 前面所有技术的一个综合应用案例：不用深度学习，怎么用二值化+连通域+特征匹配识别出文字（深度学习时代的 OCR 见 [OCR](0200_ML_Tasks_Image_OCR)，可以对比着看传统方法的局限在哪） |
| 12 | [Tools](0063_CV_Tools)                 | 动手实践用的工具集                                                                                                 |

### 第 5 步：下一步去哪

  - 想把上面这些算法**工程化、跑在实际项目里**：去
    [OpenCV](0105_OpenCV)，几乎所有经典算法都有现成的高性能实现，不需要自己从零写；
  - 想学**深度学习时代**怎么解决图像分类/目标检测/图像分割/OCR/异常检测这些任务：去 [机器学习/深度学习](0416_ML)；
  - 遇到"算法跑起来了但太慢"的问题：模型/计算层面的加速见 [模型性能优化技术](0471_MO)（量化/剪枝/蒸馏）。

## 常见场景与处理流程

把前面学到的各个技术串起来看几个真实场景的典型 Pipeline，有助于理解"这些零散的算法到底怎么组合成一个能用的系统"：

### 二维码/条形码识别

    灰度化 → 二值化(0099) → 查找连通域/轮廓，定位码的边界和定位图案
      → 透视变换校正成正对的矩形（码可能是斜着拍的）
      → 按编码规则解码出信息

### 文档/车票扫描识别（传统方法）

    灰度化 → 边缘检测(0065/Canny 0101) 或霍夫变换(0071) 找到纸张/票据的四条边
      → 透视变换把歪斜拍摄的照片"摆正"成正对的矩形
      → 二值化(0099) 把文字从背景里分离出来
      → 连通域分析做字符分割
      → 逐个字符匹配识别，详见 Traditional OCR(0199)

> 这条 Pipeline 里几乎每一步都是本页前面某个子主题的直接应用——这也是为什么建议先学完经典算法再看综合应用案例。深度学习时代的
> OCR（0200）用一个端到端模型基本替代了"二值化→分割→逐字符匹配"这几步，但"先定位文字区域再识别"这个整体思路是相通的。

### 工业零件表面缺陷检测

    相机采集（打光方案很大程度决定了后面好不好做，见下方 Reference）
      → 灰度化 → 直方图均衡(0100) 改善对比度
      → 阈值分割(0099) 或传统图像分割(0158) 圈出可疑区域（粗筛，计算量小）
      → 对可疑区域用深度学习模型做最终判定（见 工业异常检测 0277），避免对整张大图都跑一遍重模型

### 全景图拼接

    对每张待拼接的图提取 SIFT 特征点(0069)
      → 在相邻图像间做特征匹配，找到同一个点在不同图里的对应关系
      → 用匹配的点对估计图像之间的几何变换关系（单应性矩阵）
      → 把图像变换对齐后拼接、做接缝处的融合

### 车道线检测（经典方法，自动驾驶场景）

    灰度化 → 裁剪出画面下半部分的感兴趣区域（天空/两侧对车道线判断没用，先排除掉减少干扰）
      → 边缘检测(0065/Canny 0101)
      → 霍夫变换(0071) 从边缘点里拟合出直线
      → 按斜率/位置筛选出左右车道线，叠加画在原图上

### 零件计数与定位抓取

    二值化(0099) 把零件和背景分离
      → 形态学操作（腐蚀/膨胀）去掉噪点、分开粘连的零件
      → Blob Detection(0068) 或轮廓分析，找到每个独立零件的位置和外形
      → 计算每个 Blob 的质心、主轴方向，换算成机械臂抓取坐标

**共同规律**：几乎所有经典 CV Pipeline 都遵循"**全局操作（灰度化/直方图均衡）→ 分离前景背景（二值化/分割）→
提取结构（边缘/角点/特征）→
针对具体任务做进一步处理（拟合形状/匹配/分类）**"这个大致顺序，理解了这个顺序，看到一个新场景时就能大致猜出该往哪个方向拆解问题。
