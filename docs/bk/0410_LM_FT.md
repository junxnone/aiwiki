# 大模型微调

  - 微调（Fine-Tuning）：在预训练模型基础上，用下游任务数据继续训练，让模型适配特定任务/领域/风格；核心取舍是训练成本 vs
    效果上限。
  - 按"更新多少参数"分三大类：**全参数微调**（Full Fine-Tuning，含用低秩技巧省显存但仍全参数更新的
    GaLore/ReLoRA）、**参数高效微调**（PEFT，Parameter-Efficient Fine-Tuning，内部又分
    Adapter-Tuning 和 Prompting
    两条路线）；另有一个正交的维度是"用什么数据/目标函数训练"（SFT/RLHF/DPO，见文末）；
  - [DreamBooth](0405_LM_FT_DreamBooth) 是图像扩散模型领域的个性化微调技术，和下面面向语言模型的
    PEFT/Prompting 技术不是同一类任务（模态、目标都不同），放在本页只是因为都叫"微调"；更早、更轻量的同类技术见
    [Textual Inversion](0570_LM_FT_TextualInversion)。

## 全参数微调（Full Fine-Tuning）

  - 更新预训练模型的全部参数来适配下游任务，效果上限最高（能调用模型的全部容量去拟合任务），但训练成本也最高——不仅要存权重本身，还要存梯度和优化器状态（如
    Adam 需要额外两份和权重同样大小的动量/方差缓存），一个 7B 模型全参数微调所需显存通常是推理所需显存的数倍；
  - 和下面的 PEFT 方法相比，全参数微调改的是模型"知道什么"（权重里编码的知识本身可能被整体重写），PEFT
    方法更多是在"怎么用已有知识"上加一个小的可调节旋钮，原始知识基本保持不动；
  - **QLoRA**（PEFT 范畴，见下文"LoRA 家族"）是针对"微调成本太高"这个问题的关键突破之一——把预训练权重量化到
    4bit 冻结，让 LoRA 这类 PEFT 方法也能在显存有限的消费级 GPU 上微调百亿参数量级模型，详见
    [QLoRA](0567_LM_FT_QLoRA)。

### 效率优化的全参数训练：GaLore / ReLoRA

GaLore 和 ReLoRA 不是 PEFT——它们最终训练出的权重仍然是全参数、全秩的，只是借用了 LoRA
系方法"低秩"的数学工具来省训练时的显存/效率：GaLore
压缩的是**梯度和优化器状态**（不改变权重本身是全参数更新这件事），ReLoRA
则是反复做"LoRA 训练 → 合并回权重 →
重置"，用多次低秩更新的叠加去逼近一个高秩的总变化量。两者都更适合预训练/继续预训练场景，和常规下游任务微调的使用场景不太重合，详见
[GaLore/ReLoRA](0569_LM_FT_GaLoreReLoRA)。

## 参数高效微调（PEFT）

PEFT
是指：冻结预训练模型的绝大部分参数，只新增/调整一小部分参数来完成任务适配。好处除了训练成本低，还有存储成本低——同一个底座模型可以对应很多个任务各自的一小份
adapter 权重，不需要为每个任务都存一整份模型。PEFT 内部分两条路线：

  - **Adapter-Tuning**：在模型内部结构里插入或调整一小组新参数（额外的小型网络模块、低秩矩阵等），直接改变模型中间层的计算；
  - **Prompting**：不改模型内部结构，只在输入侧做文章。

### Adapter-Tuning 分支

#### 经典 Adapter

[Adapter FineTuning](0412_LM_FT_Adapter)（Houlsby et al.
2019）是这条路线最早的做法：在 Transformer
每一层里插入一个小型瓶颈（bottleneck）MLP
模块，只训练这个新插入的模块，冻结原模型参数。怎么复用多个已训练好的任务
Adapter，见 [AdapterFusion](0571_LM_FT_AdapterFusion)。

#### LoRA 家族

[LoRA](0406_LM_FT_LoRA)（Hu et al. 2021）是目前使用最广泛的 PEFT 方法：假设权重更新 ΔW
具有低秩结构，用两个低秩矩阵 B、A 的乘积近似它，只训练 B、A。LoRA 衍生出两类变种：

  - **初始化方式变种**（解决"给 A、B 选一个更好的起点"）：PiSSA、OLoRA、EVA、LoftQ、rsLoRA、DoRA，详见
    [LoRA](0406_LM_FT_LoRA) 里的"LoRA 初始化变体"一节；把 LoRA 和权重量化结合起来的 **QLoRA**
    内容量较大，已拆成独立文章；
  - **结构/机制变种**（解决"ΔW
    该用什么样的分解形式"）：[LoHa](0492_LM_FT_LoHa)（哈达玛积分解）、[LoKr](0493_LM_FT_LoKr)（Kronecker
    积分解）、[AdaLoRA](0491_LM_FT_AdaLoRA)（自适应调整各层的秩）、**X-LoRA**（多个冻结 LoRA
    专家的混合路由，见下）。

训练完多个任务各自的 LoRA 之后，生产环境怎么部署/服务，见 [多 LoRA
生产部署](0572_LM_FT_MultiLoRAServing)；不想运行时动态切换、而是想离线把多个
LoRA（或多个全参数微调模型）直接合并成一份权重，见
[模型合并](0573_LM_FT_ModelMerging)。

#### 正交微调：OFT / BOFT / HRA

[OFT/BOFT](0495_LM_FT_OFT)
用正交矩阵变换预训练权重，天然保持权重的"超球能量"不变，被认为能更好地保留预训练知识。**HRA**（Householder
Reflection Adaptation，Yuan et al. 2024 NeurIPS Spotlight）用一串可学习的
Householder
反射矩阵构造这个正交变换，证明了这在数学上等价于一种自适应的低秩适配，弥合了低秩方法和正交方法之间的理论鸿沟，用更少的参数达到比肩甚至超过
OFT 的效果。

#### 其他结构创新：Llama-Adapter、Bone

  - **Llama-Adapter**（Zhang et al. 2023）专门为把 Llama 改造成指令跟随模型设计：冻结 Llama
    本体，只在高层 Transformer 的输入指令前面学习一组"自适应提示"（adaptation
    prompt），并用**零初始化的门控注意力**机制，让这些新提示的影响从零开始、训练中逐步增大，避免新插入的随机参数一开始就扰乱模型已有的知识；
  - **Bone**（Block Affine，Kang
    2024）不走"分解成低秩矩阵"的老路，而是把原始权重切成多个子空间、共享一个更新矩阵（思路借鉴了
    GQA/MQA 的分组共享），用"Weight
    Guide"思想让可训练矩阵在训练中持续参考原始权重，收敛更快、对原始权重信息利用更充分，论文报告在
    LLaMA2-7B + MetaMathQA 上的效果超过了 LoRA 和 PiSSA；
  - **X-LoRA**：把多个训练好的、冻结的 LoRA 专家组合起来，用一个额外的轻量路由网络按
    token/层/序列粒度动态决定每个专家的混合权重（Mixture of LoRA
    Experts 思路），本身只需要训练这个小路由网络。

### Prompting 分支

  - **硬提示（hard prompts）**：人工写的、离散的自然语言文本提示，不需要训练，但写出一个好提示需要大量人工试错；
  - **软提示（soft prompts）**：和输入词向量拼接在一起的、可学习的连续向量，可以直接针对任务梯度优化，缺点是这些"虚拟
    token"不对应任何真实单词、不可读。

软提示方向的几种代表性方法：

| 方法                                                        | 核心思路                                                                                                | 和其他方法的区别                                                            |
| --------------------------------------------------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| Prompt Tuning（Lester et al. 2021）                         | 只在输入词嵌入层拼接一组可学习的连续向量，不加额外网络                                                                         | 最简单的软提示方法，但只有模型规模足够大（10B+）时效果才能接近全参数微调                              |
| P-Tuning（Liu et al. 2021）                                 | 同样在嵌入层插入连续提示，但用一个 LSTM 对提示做重参数化，让提示向量之间有更合理的相关性                                                     | 面向自然语言理解/知识探测任务设计                                                   |
| [P-Tuning v2](0411_LM_FT_PrefixTuning)（Liu et al. 2022）   | 不只在输入层插入提示，而是在模型**每一层**都插入可学习的前缀（深度提示）                                                              | 解决了前两种方法"必须模型足够大才好用、在序列标注类任务上表现差"的问题，用约 0.1% 的任务参数就能在各种规模模型上比肩全参数微调 |
| [Prefix-Tuning](0411_LM_FT_PrefixTuning)（Li & Liang 2021） | 在每一层的 Key/Value 前面拼接一段可学习的前缀向量                                                                      | 最早提出"每层插入可学习前缀"思路的工作之一，面向文本生成任务                                     |
| 多任务提示调整（Multitask Prompt Tuning, MPT, Wang et al. 2023）   | 先从多个任务各自训练出的软提示里蒸馏出一个共享提示，再给每个下游任务学一个低秩的任务专属调整量（共享提示和任务调整量做哈达玛积）                                    | 解决"每个任务都要从头训练一个独立软提示"的问题，让多任务之间的知识可以共享、迁移                           |
| CPT（Context-Aware Prompt Tuning, 2024）                    | 把提示调整和上下文学习（In-Context Learning）结合：直接优化拼接在输入里的示例（demonstration）本身的嵌入，而不是另加一组虚拟 token，并借鉴对抗训练思路做约束优化 | 目标是同时吸收 ICL 不容易过拟合、提示调整效果更稳定这两者的优点                                  |

## 怎么选

| 场景                                 | 推荐                                                                            |
| ---------------------------------- | ----------------------------------------------------------------------------- |
| 追求效果上限，不在乎训练成本，算力充足                | 全参数微调                                                                         |
| 常规下游任务微调，显存/存储有限，要支持多任务共享底座        | LoRA（最通用、生态最成熟）                                                               |
| 显存非常紧张（如单卡消费级 GPU 微调几十上百亿参数模型）     | QLoRA                                                                         |
| 对 LoRA 效果不满意，想进一步逼近全参数微调质量         | DoRA、PiSSA 等初始化变种，或 OFT/HRA                                                   |
| 扩散模型"让模型记住某个特定主体"                  | DreamBooth（还原细节优先）或 [Textual Inversion](0570_LM_FT_TextualInversion)（轻量/风格优先） |
| 只想要极少量可训练参数，能接受效果上限略低              | P-Tuning v2 / Prefix-Tuning                                                   |
| 需要让一个底座同时服务多个任务、相互共享知识             | 多任务提示调整（MPT）或 X-LoRA                                                          |
| 要（继续）预训练，显存/优化器状态是瓶颈，但要保留全参数更新能力   | GaLore / ReLoRA                                                               |
| 已经有 SFT 数据，想让模型更符合人类偏好             | DPO 及其变种（工程最简单）或 RLHF（需要独立奖励信号时）                                              |
| 多个任务/用户各自的 LoRA 需要同时在线服务           | [多 LoRA 生产部署](0572_LM_FT_MultiLoRAServing)（S-LoRA/vLLM multi-LoRA）            |
| 想把多个已训练好的模型/adapter 能力融合进一个，且不想再训练 | [模型合并](0573_LM_FT_ModelMerging)（SLERP/TIES/DARE）                              |
| 微调完想知道效果到底好不好                      | [微调效果评估](0574_LM_FT_Evaluation)（AlpacaEval/MT-Bench）                          |

## PEFT 之外：训练目标层面的微调概念

本页聚焦"用什么方式更新参数"，还有一组概念是"用什么数据/目标函数来微调"，两者是正交的、可以自由组合（比如可以用 LoRA 做
SFT，也可以全参数做 SFT）：

  - **SFT（Supervised
    Fine-Tuning，监督微调）**：用"指令-回答"这样的数据对，让预训练模型学会按指令格式回应，是目前几乎所有对话类大模型训练流程里的标准一步，可以用全参数微调也可以用上面任意一种
    PEFT 方法实现；
  - **RLHF（Reinforcement Learning from Human Feedback）**：在 SFT
    之后，先训练一个奖励模型学习人类偏好，再用强化学习（通常是
    PPO）让模型朝奖励模型打分更高的方向继续优化，最早在
    InstructGPT（2022）里被证明能显著提升模型的有用性和安全性；
  - **DPO（Direct Preference Optimization，Rafailov et al.
    2023）**：绕开"训练单独的奖励模型 + 强化学习"这套复杂流程，直接用偏好数据对（更好的回答
    vs 更差的回答）构造一个简化的损失函数做监督式优化，实践中更稳定、更容易调参，是目前 RLHF 之外最主流的对齐训练方法，后续还衍生出
    IPO/KTO/ORPO/SimPO 等变种。

这三者描述的是"用什么数据和损失函数训练"，不是"怎么更新参数"，和本页的 PEFT 方法不在同一个分类维度上，详见
[大模型对齐训练：SFT/RLHF/DPO](0568_LM_FT_Alignment)；微调/对齐训练完之后怎么评估效果，见
[微调效果评估](0574_LM_FT_Evaluation)。
