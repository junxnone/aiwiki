# 算法落地实践

> 本文是 [Image Anomaly Detection](0277_ML_Tasks_Image_Anomaly)
> 的子篇，讲算法从"跑在论文 Benchmark
> 上"到"跑在产线上"中间要解决的工程问题：怎么定需求、怎么选相机和打光、怎么选算法和评估指标、怎么部署到边缘设备并持续迭代。

## 需求

工程落地前要先把这些问题问清楚，它们直接决定后面硬件和算法怎么选：

  - **缺陷类型**：决定用哪类算法（表面划痕 vs 尺寸缺失 vs 色彩异常，对应的最优打光/算法分类都不同）
  - **缺陷大小（Max/Min）**：决定相机分辨率下限——最小缺陷尺寸必须能被足够多的像素覆盖才能被稳定检出（见下文"镜头选型与分辨率计算"）
  - **缺陷位置**：是否固定在特定区域，决定是否可以用 ROI（感兴趣区域）裁剪来减少计算量、提高帧率
  - **缺陷色彩**：决定是否需要彩色相机、是否需要特定波段光源（如检测透明异物可能需要红外/紫外光）
  - **缺陷对比度**：低对比度缺陷（如同色系划痕）往往不是算法问题而是打光问题——选对光源比换更复杂的模型更有效
  - **时间需求**：拆解为采集时间/传输时间/算法时间/执行机构动作时间，总和不能超过产线节拍时间（Takt
    Time，即产线上处理一个工件允许的最长时间，由产线速度反推）；算法推理时间的压缩手段见下文"边缘部署与加速"
  - **良率指标与漏检/误检权衡**：工业场景几乎总是**漏检（False Negative，有缺陷判成合格）的代价远高于误检（False
    Positive，合格品判成缺陷）**——误检只是多一次人工复检，漏检可能是不良品流出。算法阈值的选择要按这个不对称代价来定，而不是简单地看整体准确率

## 硬件

### 相机选型

  - 待检测物体尺寸，拍摄视野预留 20%\~30% 冗余（避免工件在视野边缘抖动被裁切）
  - 最小待检测缺陷、算法能够稳定检测的最小像素 N×N、计算图片最小分辨率：三者层层递推，见下文公式
  - **面阵相机（Area Scan）vs 线扫相机（Line
    Scan）**：静止或节拍式停留拍摄用面阵相机；连续运动的卷材/带材（钢板、织物、薄膜）通常用线扫相机，逐行成像再拼接成图，此时还要额外核算行频（见下文公式）
  - 接口带宽（GigE/USB3/CoaXPress）要覆盖"分辨率 × 帧率"的数据吞吐量，否则传输时间会吃掉节拍时间预算
  - 综合处理时间（采集+传输+算法）反过来约束相机帧率/分辨率的上限选择

### 镜头选型与分辨率计算

把"最小缺陷尺寸"换算成"相机该选多少像素"是个标准的反推公式：

$$ 单像素精度（mm/pixel）= \\frac{视野范围 FOV（mm）}{相机分辨率（pixel）} $$

要稳定识别一个缺陷边缘，通常需要多个像素覆盖同一特征（**过采样**，经验值 2-3 倍，对应奈奎斯特采样定理——要分辨 N lp/mm
的线对，至少需要 2N/mm 的采样密度），所以反推相机最小分辨率的公式是：

$$ 相机分辨率（pixel）\\geq \\frac{视野范围（mm）}{最小缺陷尺寸（mm）}\\times 过采样倍数（通常
2{\\sim}3） $$

镜头本身的分辨率用线对/毫米（lp/mm）表示，镜头能分辨的最小尺寸 = 1 / (2 × 镜头分辨率)。光学放大倍率、焦距、工作距离满足：

$$ 放大倍率 = \\frac{传感器尺寸（短边）}{视野（短边）} = \\frac{焦距}{工作距离} =
\\frac{像元尺寸}{可分辨精度} $$

线扫相机场景额外需要核算行频：行频（line rate）= 运动速度 / 实际检测精度，曝光时间需小于 1/行频，最低帧率 = 运动速度 /
视野长度。

### 打光方案

打光选对了，很多"需要更强算法"的问题直接消失；是机器视觉工程里投入产出比最高的一环，常见光源类型及适用场景：

| 光源类型                      | 原理                              | 适用缺陷/场景                                |
| ------------------------- | ------------------------------- | -------------------------------------- |
| **背光源（Backlight）**        | 从物体后方照射，物体在画面里呈剪影轮廓             | 尺寸测量、外形/轮廓检测、透明物瑕疵——只关心轮廓信息、不关心表面纹理的场景 |
| **同轴光源（Coaxial）**         | 通过分光镜让光线与相机光轴平行入射，消除表面不平整产生的阴影  | 高反光表面（金属/玻璃/薄膜/晶圆）的划痕、芯片/硅片损伤检测、标记点定位  |
| **环形光源（Ring Light）**      | 环形排列的光均匀照射，高角度减阴影、低角度（暗场）凸显表面形貌 | 电子元件/标签/字符检测；低角度暗场常用于金属表面瑕疵、PCB 定位     |
| **条形光源（Bar Light）**       | 窄条光斜角照射，形成线状光带                  | 高反光表面的微小划痕（斜射角减少正面反射干扰），如印刷质量、钢板表面检测   |
| **穹顶光源（Dome Light，无影灯）**  | 半球内壁漫反射 360° 光线，整体照度均匀无阴影       | 曲面/凹凸表面、强反光的金属或玻璃表面（球形工件、瓶类容器等）        |
| **结构光（Structured Light）** | 投射光栅/线光源，根据畸变反解三维形貌             | 需要获取三维高度信息的检测场景（而非单纯二维纹理异常）            |

选型总体逻辑：要**轮廓/尺寸/透明体**信息优先选背光（剪影效应，忽略表面纹理）；要**表面划痕/字符**信息优先选同轴光或低角度环形/条形光（强化表面起伏）；曲面/强反光优先选穹顶光；需要三维信息才上结构光。

### 远心镜头与精密测量

普通镜头是中心投影，离镜头越远的物体成像越小（"近大远小"），同一个工件如果因为传送带抖动在景深方向前后移动几毫米，测出来的尺寸就会跟着变——这对"缺陷大小测量"类需求是致命的。\*\*远心镜头（Telecentric
Lens）\*\*通过限制光路只采集与光轴平行的光线，让放大倍率在一定景深范围内基本不随物距变化，是精密尺寸测量、2D
轮廓度量场景的标配镜头，代价是体积大、价格高、且镜头直径必须大于等于被测物尺寸（没有"变焦"空间）。不是所有场景都需要远心镜头——纯粹的外观/纹理缺陷检测通常用性价比更高的普通工业镜头即可。

### 相机标定（Camera Calibration）

把图像里的像素坐标换算成真实物理尺寸（或者多台相机的坐标系对齐）之前，需要先做标定：

  - **内参标定**：确定焦距、主点、镜头畸变系数（径向/切向畸变），常用棋盘格标定板 +
    张正友标定法；畸变校正后图像里的直线才能在画面各处都保持"直"，这是精确测量的前提；
  - **外参标定**：确定相机相对于世界坐标系（如产线/机械臂坐标系）的位置和姿态，多相机拼接、或者要把"图像里的缺陷位置"换算成"产线上的物理坐标"（比如指挥机械臂去剔除）时必须做；
  - 标定不是一次性的——镜头/相机如果被重新拆装或受到震动移位，标定参数就会失效，需要定期复检。

### 触发同步

相机、光源、产线运动三者的时序必须对齐，否则要么拍到运动模糊的图，要么光源还没稳定亮起就曝光了：

  - **硬件触发**：用编码器脉冲（Encoder
    Trigger，和产线运动位置绑定，而不是固定时间间隔触发——这样即使产线速度波动，拍摄位置依然准确）或光电传感器（工件到位触发）给相机发触发信号；
  - **频闪同步（Strobe
    Sync）**：相机触发的同时给光源一个短脉冲、高亮度的闪光（而不是光源常亮），既能用极短曝光时间冻结运动模糊，又比常亮节能、减少光源发热老化；
  - 时序设计要核算：触发延迟 + 光源响应时间 + 曝光时间之和必须小于工件在视野内停留/经过的时间窗口。

### 多相机 / 3D 视觉落地

当二维纹理信息不足以判断缺陷（如凹陷/凸起类缺陷在特定光照角度下可能完全不可见）时，需要引入三维信息：

  - **多目立体视觉（Stereo
    Vision）**：两个或多个已标定的相机从不同角度拍摄同一物体，通过视差计算深度，适合大尺寸工件的三维轮廓重建；
  - **结构光 3D
    重建**：配合前文"打光方案"里的结构光投影，通过条纹/散斑图案的畸变反解出高精度的高度图，常见于小型精密零件的三维缺陷（凹坑、凸起、高度差）检测；
  - 3D 方案的数据量和处理时间通常显著高于 2D 方案，上线前要核实能否压进节拍时间预算（见前文"时间需求"）。

## 算法改善成像质量

  - **白平衡矫正**：校正光源色温偏差，让白色物体在图像里依然呈现白色，避免色偏干扰颜色相关的缺陷判断
  - **平场矫正（Flat-field
    Correction）**：用一张均匀背景的参考图估计光照不均/镜头渐晕（Vignetting）造成的亮度衰减模式，再用这个参考图去除实拍图像里的不均匀亮度，避免视野边缘因为变暗被误判为异常
  - **颜色矫正**：用色彩校正矩阵（Color Correction
    Matrix）把相机传感器响应和人眼/标准色彩空间对齐，是色彩相关缺陷判断准确的前提

> 通常 相机软件自带功能 `白平衡矫正` 和 `平场及平场矫正`

### 图像预处理算法

硬件层面的矫正解决的是成像系统本身的系统性偏差，软件层面的预处理算法则是在送进检测模型之前，针对具体缺陷类型再做一次信噪比提升：

  - **去噪**：高斯/中值滤波抑制传感器噪声，但要注意滤波强度不能把细小的真实缺陷一起模糊掉——去噪参数要用实际的小缺陷样本验证，而不是只看视觉上"干净"；
  - **锐化**：反锐化掩模（Unsharp Masking）等方法增强边缘，对比度低的划痕类缺陷经常受益；
  - **对比度增强**：直方图均衡化（含限制对比度的 CLAHE）、Gamma 校正，让本来隐藏在暗部/亮部的细节变得可辨；
  - 这些预处理步骤要么在相机/采集卡的 ISP
    硬件里做（延迟低，不占用后端算力），要么在算法前处理阶段做（更灵活，可按缺陷类型调参）——具体放在哪一层主要由延迟预算和灵活性需求决定。

### 评估

  - **色彩还原度的检测**：拍摄标准色卡（如 ColorChecker），比较采集色值和色卡标定值的偏差
  - **图像噪声检测（成像稳定性）**：拍摄均匀灰板/平场图像，统计像素值的标准差，评估传感器噪声水平
  - **图像清晰度（SFR）**：按 ISO 12233 斜边法（Slanted Edge
    Method）测量空间频率响应，是镜头+传感器组合分辨能力的标准化指标
  - **连续采集稳定性**：长时间连续拍摄同一标定物，监控曝光/色彩/清晰度是否随时间漂移（如光源老化、温度漂移）

## 算法选型与部署流程

### 算法选型

按缺陷类型、数据量、是否要支持多产品复用来选算法类别，具体分类和代表方法见 [Image Anomaly
Detection](0277_ML_Tasks_Image_Anomaly)：

  - 新产品、缺陷样本极少甚至没有 → 优先考虑零/少样本 VLM 方案
  - 单一产品、有一定量正常样本可采集 → 记忆库/知识蒸馏类方法性价比高，PatchCore 是常用强基线
  - 需要一套模型覆盖多个产品型号 → 考虑 UniAD/Dinomaly 这类统一多类模型，避免每上线一个新产品就重新训练一套

### 评估指标与阈值选择

  - 常用指标：Image/Pixel 级
    AUROC、F1，工业场景还要单独看**漏检率（FNR）**和**误检率（FPR）**，而不是只看一个综合分数；
  - 阈值选择本质是在 ROC 曲线上，结合"漏检代价 ≫ 误检代价"这个业务约束去选一个工作点，而不是用默认的 0.5
    或者"精度最高"的点。

### 边缘部署与加速

产线现场通常是嵌入式/边缘算力，而不是云端 GPU，模型推理时间要压进节拍时间预算里。常用加速手段（具体技术细节见
[模型性能优化技术](0471_MO)）：

  - **量化**：INT8/INT4 压缩推理延迟和内存占用，见 [量化](0312_MO_Quantization)
  - **剪枝**：裁掉冗余参数/通道，减少计算量
  - OpenVINO 等推理框架（结合 Intel CPU/iGPU/VPU）是工业视觉场景常见的部署路径

### 可解释性

产线操作员需要知道"为什么判它是缺陷"，而不只是一个分数——PaDiM/PatchCore
等方法天然能输出像素级异常热力图，叠加在原图上展示给操作员，是获得产线信任、方便人工复检定责的关键环节。

## 系统集成与产线通信

模型吐出一个"合格/不合格"的判断，只是整个闭环里的一步——怎么把这个判断变成产线的实际动作，是"落地"真正的最后一公里：

  - **与 PLC/MES 的通信协议**：工业现场常见的是 **OPC-UA**（新一代、支持更丰富的数据模型和安全机制）或
    **Modbus
    TCP/RTU**（更老、更轻量、至今仍大量存在于存量设备里），视觉系统要作为"从站"或"客户端"把检测结果（合格/不合格/具体缺陷类型/坐标）写入约定好的寄存器或节点，供
    PLC/MES 读取；
  - **I/O 信号层**：最简单直接的集成方式——检测结果直接通过数字
    I/O（如继电器输出的高低电平）触发产线上的分拣气缸、报警灯、停机信号，不经过复杂的协议栈，延迟最低、也最可靠，很多产线的"最终判定动作"仍然走这条路径而不是纯软件通信；
  - **结果到动作的映射**：合格 → 放行；不合格 →
    触发分拣机构把工件推离产线（这里要核算气缸动作时间是否还能赶上产线速度）；介于阈值附近的"疑似"结果
    → 路由到人工复检工位而不是直接判定，避免把阈值选择的不确定性直接转嫁成误检/漏检；
  - **多工位/多算力调度**：产线上如果有多个检测点位同时运行，要规划好每个点位用独立算力还是共享一套边缘服务器排队处理，后者要核算排队等待时间是否会突破单个工位的节拍时间预算。

## 数据闭环与模型运维

产线会不断引入新产品型号、新的缺陷种类，模型上线不是终点，而是一个需要持续运营的闭环的起点：

  - **数据回流**：产线上人工复检纠正的误检/漏检案例，要回流进标注流程，变成下一轮训练/增量更新的数据——没有这条回路，模型效果只会随着产品/环境的漂移慢慢变差；
  - **重训练触发条件**：常见的触发方式有固定周期（如每月）、累积新增样本量达到阈值、或者监控到线上漏检率/误检率超过预设告警线时触发，而不是"等出了问题才想起来重训"；
  - **增量更新 vs 从头重训**：新增产品/缺陷类型时，理想情况下只增量更新而不是从头重训全部数据，具体做法（如 PatchCore 的
    Coreset 增量合并）见 [增量学习/持续学习](0536_ML_IL)、[PatchCore
    持续学习](0537_ML_IL_PatchCore)；
  - **上线前的 A/B 测试/灰度发布**：新模型先在少数几个工位/一部分流量上和旧模型并行跑（Shadow
    Mode，只记录不决策，或者小流量灰度），对比漏检率、误检率、推理耗时都不劣化于旧版本，再逐步扩大到全部产线；
  - **回滚机制**：每次上线都要保留旧版本模型和配置，一旦灰度或全量后发现指标异常，能够立刻切回上一个稳定版本，而不是现场紧急调试；
  - **版本管理**：模型版本、对应的训练数据快照、评估报告要一一对应可追溯——出现批量误判需要复盘时，能准确定位到"当时跑的是哪个模型、用了哪批数据训练的"。
