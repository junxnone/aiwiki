# 剪枝流程与时机

剪枝不只是「选哪些权重」，还有「**什么时候剪、剪几次**」。时机不同，所需的数据、算力和最终精度都不同。系列总览见
[剪枝](https://github.com/junxnone/aiwiki/issues/808)，评分方法见
[重要性准则](https://github.com/junxnone/aiwiki/issues/810)。

## 三种时机

``` mermaid
flowchart LR
    A[训练前剪枝 初始化时] --> B[训练中剪枝 逐步稀疏]
    B --> C[训练后剪枝 预训练模型]
    C --> D[微调恢复精度]
```

图中：三种方式分别发生在训练的不同阶段；训练后剪枝通常要紧跟微调来恢复精度。

| 时机  | 做法                        | 代表                 | 特点                |
| --- | ------------------------- | ------------------ | ----------------- |
| 训练前 | 在随机初始化时用一批数据评分，一次剪好，再从头训练 | SNIP、GraSP、SynFlow | 节省训练开销，但精度通常不及后两者 |
| 训练中 | 稀疏度随训练逐步增加，或动态调整掩码        | 渐进式幅度剪枝、RigL、SET   | 精度好，训练和剪枝一次完成     |
| 训练后 | 对预训练好的模型一次性或迭代剪枝，再微调      | 幅度剪枝 + 微调、OBS 类    | 最常用，尤其是 LLM       |

表中：对比结论：能拿到预训练模型时，训练后剪枝最方便；需要从头训练且想省算力时，才考虑训练前剪枝。

## 一次性 vs 迭代

  - **一次性（one-shot）**：一次剪到目标稀疏度，然后微调。简单，但稀疏度高时精度下降大
  - **迭代（iterative）**：重复「剪一点 → 微调」多轮，每轮剪一部分。精度更好，但耗时多

迭代剪枝每轮的稀疏度按比例递增：

$$ s\_k=1-(1-r)^k $$

其中：$r$ 是每轮剪掉剩余权重的比例（如 20%）；$k$ 是轮数；$s\_k$ 是 $k$ 轮后的累计稀疏度。例如 $r=0.2$，经过
$k=5$ 轮：$s\_5=1-0.8^5\\approx0.67$。

## 渐进式幅度剪枝

训练过程中，稀疏度从初始值平滑上升到目标值（Zhu & Gupta 的三次多项式调度）：

$$ s\_t=s\_f+(s\_i-s\_f)\\left(1-\\frac{t-t\_0}{n,\\Delta t}\\right)^{3}
$$

其中：

  - $s\_t$：第 $t$ 步的目标稀疏度；$s\_i$：初始稀疏度（常为 0）；$s\_f$：最终稀疏度
  - $t\_0$：开始剪枝的步数；$n$：剪枝的次数；$\\Delta t$：相邻两次剪枝间隔的步数
  - 三次方使前期剪得快（冗余多），后期放慢（剩余权重更重要），给网络恢复的时间

## 彩票假说（Lottery Ticket Hypothesis）

稠密网络中存在一个稀疏子网络（「中奖票」），若用**原始初始化**单独训练，可以达到与原网络相当的精度。寻找方法是迭代幅度剪枝（IMP）：

1.  随机初始化网络，保存初始权重 $\\theta\_0$
2.  训练到收敛，剪掉幅度最小的 $p%$ 权重，得到掩码 $M$
3.  把剩余权重**重置回** $\\theta\_0$（或训练早期的权重，称为 rewinding）
4.  重复 2 到 3，直到达到目标稀疏度

其中 $p$ 是每轮剪枝比例。对更大的网络，重置到初始值通常无效，需要「回退到训练早期」的权重（late
rewinding）。意义：说明稀疏结构本身（而不仅是权重值）蕴含了学习能力，但寻找代价高（要多轮完整训练）。

## 训练前剪枝：SNIP

用一批数据计算各连接的敏感度，一次性剪枝：

$$ S\_j=\\frac{\\left\\lvert
g\_j,w\_j\\right\\rvert}{\\sum\_{k}\\left\\lvert
g\_k,w\_k\\right\\rvert} $$

其中：$g\_j=\\partial\\mathcal{L}/\\partial w\_j$ 为在初始点用一个 mini-batch
得到的梯度；$w\_j$ 为初始权重；分母做归一化。得分最小的连接被剪掉，随后正常训练。

## 动态稀疏训练

不训练稠密网络，而是**始终保持稀疏**，在训练中不断更新掩码：

| 方法   | 剪（drop） | 长（grow） |
| ---- | ------- | ------- |
| SET  | 幅度最小的权重 | 随机位置    |
| RigL | 幅度最小的权重 | 梯度最大的位置 |

表中：每隔一定步数，剪掉一部分权重，同时在别处长出同样数量的新连接，使总稀疏度保持不变。RigL
利用梯度信息选择新连接，通常比随机效果好。对比结论：动态稀疏训练的训练和推理成本都低，但需要稀疏训练的框架支持才能真正省算力。

## 实践流程

``` mermaid
flowchart LR
    A[训练稠密模型] --> B[评估重要性并剪枝]
    B --> C[微调]
    C --> D{达到目标?}
    D -- 否 --> B
    D -- 是 --> E[在目标硬件上评估速度和精度]
```

图中：经典的「训练 → 剪枝 → 微调」循环，直到满足目标稀疏度，最后在真实硬件上验证（避免「稀疏了但不快」，见
[基础原理](https://github.com/junxnone/aiwiki/issues/809)）。

  - 微调的学习率通常小于原训练的学习率
  - 每次不要剪得太猛，层间稀疏度分配要谨慎，输入输出附近的层通常更敏感
  - 剪枝可与蒸馏同时进行，用 [知识蒸馏](https://github.com/junxnone/aiwiki/issues/207)
    损失恢复精度
