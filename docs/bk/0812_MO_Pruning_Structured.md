# 结构化剪枝

结构化剪枝移除**整个结构**：通道、卷积核（滤波器）、注意力头、整层。剪完得到一个规则的、更小的稠密模型，不需要稀疏硬件就能直接加速。系列总览见
[剪枝](https://github.com/junxnone/aiwiki/issues/808)，粒度对比见
[基础原理](https://github.com/junxnone/aiwiki/issues/809)。

## 通道剪枝的耦合关系

``` mermaid
flowchart LR
    C1[Conv1 输出通道 i] --> B1[BN1 第 i 个参数]
    B1 --> R[ReLU]
    R --> C2[Conv2 输入通道 i]
```

图中：剪掉 Conv1 的第 $i$ 个输出通道，必须同时移除紧随其后的 BN 的第 $i$ 组参数，以及下一层卷积的第 $i$
个输入通道。这种依赖要成组处理，否则张量形状对不上。

通道剪枝对计算量的影响：

$$ \\text{FLOPs}=2,C\_{in},C\_{out},K^{2},H,W $$

其中：$C\_{in}$、$C\_{out}$ 为输入、输出通道数；$K$ 为卷积核大小；$H,W$ 为输出特征图的高宽。

  - 把某层输出通道剪掉比例 $p$，则该层 $C\_{out}$ 变为 $(1-p)C\_{out}$，同时下一层的 $C\_{in}$
    也缩小 $(1-p)$
  - 因此相邻两层的计算量约各降 $p$（连续多层各自剪枝时，近似按 $(1-p)^2$ 缩减）

## 常用方法

| 方法               | 做法                                                     | 要点                                                            |
| ---------------- | ------------------------------------------------------ | ------------------------------------------------------------- |
| 滤波器范数            | 按每个滤波器权重的 L1/L2 范数排序，剪最小的                              | 简单有效，见 [重要性准则](https://github.com/junxnone/aiwiki/issues/810) |
| Network Slimming | 训练时对 BN 的 $\\gamma$ 加 L1 正则，使不重要通道的 $\\gamma\\to0$，再剪掉 | 与训练结合，通道分数天然可比                                                |
| 重构误差（ThiNet 等）   | 选一组通道，使下一层输出的重构误差最小                                    | 精度好，计算量较大                                                     |
| 基于梯度/泰勒          | 用泰勒展开估计去掉通道的损失变化                                       | 能考虑任务损失                                                       |
| 自动结构搜索           | 用 NAS 或强化学习搜每层通道数                                      | 见 [NAS](https://github.com/junxnone/aiwiki/issues/392)        |

表中：对比结论：入门用滤波器范数；追求精度时用与训练结合的方法。

Network Slimming 的训练目标：

$$
\\mathcal{L}=\\mathcal{L}*{task}+\\lambda\\sum*{c}\\lvert\\gamma\_c\\rvert
$$

其中：$\\mathcal{L}\_{task}$ 为任务损失；$\\gamma\_c$ 为第 $c$ 个通道的 BN
缩放因子；$\\lambda$ 为稀疏正则强度。训练后 $\\lvert\\gamma\_c\\rvert$
很小的通道对输出贡献小，可整体删除。

## 依赖关系的自动处理

复杂网络里，残差连接、拼接（concat）、分组卷积使得「一次剪哪些通道」互相牵连：

  - 残差相加要求两个分支的通道数一致，所以相关层要**一起**剪同样的通道
  - 工具会先构建依赖图，把必须同步剪的参数分成一组，再按组打分，例如 DepGraph（见
    [工具](https://github.com/junxnone/aiwiki/issues/815)）

## Transformer 的结构化剪枝

| 结构       | 剪什么                  | 说明                 |
| -------- | -------------------- | ------------------ |
| 注意力头     | 整个 head              | 研究发现很多头可以去掉而精度几乎不变 |
| FFN 中间维度 | 隐藏层神经元               | 按重要性去掉一部分          |
| 整层       | 某些 Transformer block | 深层模型里的冗余层可以移除      |
| 嵌入维度     | 隐层宽度                 | 影响所有层，需要统一处理       |

表中：对比结论：宽度（头、神经元）剪枝保持深度不变，层剪枝降低延迟更明显。LLM 上的做法见 [LLM
剪枝](https://github.com/junxnone/aiwiki/issues/814)。

## 优缺点

| 对比项       | 结构化剪枝    | 非结构化剪枝      |
| --------- | -------- | ----------- |
| 硬件加速      | 通用硬件直接受益 | 需要稀疏内核或硬件   |
| 压缩率（同等精度） | 较低       | 较高          |
| 剪完的模型     | 规则的小模型   | 与原结构相同的稀疏矩阵 |
| 恢复精度      | 通常需要较长微调 | 通常较容易       |

表中：对比结论：追求实际加速选结构化；追求参数量最大压缩选非结构化加稀疏硬件。
