# N:M 半结构化稀疏

N:M 稀疏要求：**每连续 $M$ 个权重中，最多保留 $N$ 个非零**。最典型的是 2:4（每 4 个保留 2 个，稀疏度
50%）。它介于非结构化和结构化之间：模式规则到硬件可以识别，粒度又细到精度损失较小。系列总览见
[剪枝](https://github.com/junxnone/aiwiki/issues/808)，粒度对比见
[基础原理](https://github.com/junxnone/aiwiki/issues/809)。

## 2:4 稀疏模式

$$ \\forall\\ \\text{组}\\ g=(w\_{4j},\\dots,w\_{4j+3}):\\quad \\lVert
M\_g\\rVert\_0\\le 2 $$

其中：$g$ 为权重按行方向每 4 个一组；$M\_g$ 为该组的掩码；约束要求每组最多 2 个非零。因此整个矩阵的稀疏度正好是
50%，而且**分布均匀**，每组都一样。

例：一组 4 个权重 $(0.9,,0.1,,-0.8,,0.05)$ 按幅度保留最大的 2 个：$(0.9,,0,,-0.8,,0)$。

## 为什么硬件能加速

NVIDIA Ampere 及之后的 GPU 在 Tensor Core 里原生支持 2:4 稀疏（Sparse Tensor Core）：

  - 每组只存 2 个非零值，外加每个非零值在组内位置的 2 位索引（元数据）
  - 计算时按索引从另一个矩阵里挑出对应的元素，只做 2 次乘法而不是 4 次，理论上数学吞吐翻倍

存储量（以 FP16 为例）：

$$ \\underbrace{4\\times16}*{\\text{稠密}}=64\\ \\text{bit}\\
\\longrightarrow\\
\\underbrace{2\\times16}*{\\text{非零值}}+\\underbrace{2\\times2}\_{\\text{索引}}=36\\
\\text{bit}\\ (\\approx56%) $$

其中：稠密时一组 4 个 FP16 占 64 位；2:4 稀疏时存 2 个值（32 位）和 2 个 2 位索引（4 位），共 36
位，约为稠密的 56%。所以存储不是减半而是略高于一半；理论计算加速最高约 2 倍，实际取决于矩阵形状和内存带宽。

## 流程

``` mermaid
flowchart LR
    A[训练稠密模型] --> B[按 2:4 幅度剪枝]
    B --> C[用原训练流程微调 保持 2:4 掩码]
    C --> D[导出压缩格式 非零值加索引]
    D --> E[在 Sparse Tensor Core 上推理]
```

图中：先训练稠密模型，一次性按 2:4
模式剪枝，再用原来的超参数和训练数据微调，让精度恢复；最后转换成压缩存储格式，由支持稀疏的内核执行。NVIDIA
的 ASP（Automatic SParsity）工具就是按这个流程提供的。

## 精度与收益

| 对比项     | 稠密   | 2:4 稀疏     |
| ------- | ---- | ---------- |
| 稀疏度     | 0%   | 50%        |
| 存储      | 100% | 约 56%（含索引） |
| 矩阵乘理论吞吐 | 1×   | 最高约 2×     |
| 精度      | 基线   | 微调后通常接近基线  |

表中：

  - 精度损失通常很小，因为每 4 个里选 2 个的自由度仍然较大
  - 实际端到端加速小于 2×：注意力、归一化、激活等非矩阵乘部分不受益，小矩阵或访存受限的场景提升有限
  - 对比结论：2:4 是少数「不需要大幅改模型结构、却能在专用硬件上获得真实加速」的稀疏方案

## 与量化叠加

2:4 稀疏可与 INT8 等量化同时使用，两者的收益相乘；先稀疏再量化，或稀疏微调时同时做量化感知训练（见
[QAT](https://github.com/junxnone/aiwiki/issues/703)）。

## 局限

  - 依赖特定 GPU 架构（Ampere 及以上），其他硬件（如大多数 CPU）没有对应的稀疏内核
  - 只有 50% 的固定稀疏度，不能获得更高的压缩率
  - 矩阵维度需满足对齐要求

更高稀疏度的 N:M（如 1:4、1:8）需要新的硬件或软件内核支持。LLM 上的 2:4 剪枝见 [LLM
剪枝](https://github.com/junxnone/aiwiki/issues/814)，框架支持见
[工具](https://github.com/junxnone/aiwiki/issues/815)。
